# Plan — T098: Full regression + coverage gate (Phase 9 sweep — stabilize)

## Objective (from card)

Stabilize the tree before the M9 milestone: hunt and fix the accumulated flake docket, wire a
**real** coverage gate (≥80% api services + `packages/ai`) as a CI requirement, and add a Playwright
web E2E smoke (landing + one food page). Accept: coverage gate enforced + three consecutive full
green gate runs, evidenced honestly.

## 0. READ THIS FIRST — the two honesty rules that govern this card

**H1 — "3 consecutive full CI runs green (journal links)" cannot be satisfied literally here.**
This environment cannot trigger, observe, or link a GitHub Actions run. Fabricating a run id or a
`github.com/.../actions/runs/...` link is an instant FAIL and a violation of the repo's "never
fabricate a number" rule (`docs/PERFORMANCE.md:6-8` precedent).

The **only** permitted substitute, which this plan mandates:

- 3 consecutive **full LOCAL gate runs**, cold / zero turbo cache, of the *entire* CI command set
  (§Step 12), all green, with the real per-workspace test counts and exit codes recorded in
  `docs/qa/regression-gate.md` and the journal.
- That document and the journal must state, verbatim and unhedged: **"No GitHub Actions run has been
  executed or observed for T098. The three runs below are LOCAL full-gate runs. The real-CI green
  requirement is founder-verifiable on the next push and is recorded as OPEN."**
- The M9 readiness statement (§Step 14) carries the same caveat.

**H2 — a gate born red, or a threshold tuned to fit, is dishonest.**
Coverage numbers must be **measured before** any threshold is written (§Step 2). No threshold
anywhere in this repo may be lowered by this task — not lighthouse `minScore`, not the api
`coverageThreshold` (currently `statements/lines/functions 80`, `branches 70`), not any count floor
in any existing test. If a measurement comes in under a bar, the response is *close the gap or
narrow the scope with a written justification*, never *lower the number*. If neither is possible
inside this plan, write `loop/plans/T098.blocked.md` — do not improvise.

### Step 2 — MEASURE coverage before writing any threshold (H2)

**2a — api.** `pnpm --filter @pawcareright/api test:cov` (config already exists:
`collectCoverageFrom: ["src/**/*.service.ts"]`, `coverageThreshold.global = 80/80/80/70`).
Capture the full per-file table. Record in `docs/qa/regression-gate.md`:
- the global four numbers,
- **every `*.service.ts` file below 80% statements** (name + number), if any.

Then:
- If **every** service file is ≥ 80% statements → add a per-path threshold to
  `apps/api/package.json`'s `jest.coverageThreshold`:
  `"src/**/*.service.ts": { "statements": 80 }`. This is a real strengthening (today a single
  20%-covered service can hide behind the global average) and it is **born green**, which is the
  only acceptable way to add it.
- If **any** service file is below 80% → do **not** add the per-path key (a red-born gate is
  forbidden) and do **not** touch the global numbers. Instead record the exact deficit list in
  `docs/qa/regression-gate.md` under a heading "Known coverage gaps (NOT closed by T098)" and carry
  it to the journal. Closing service-level gaps is new test work, out of this card's scope.
- **Never** change the existing global values in either direction. `branches: 70` is pre-existing
  (T020); it is not lowered, and raising it is out of scope.

**2b — packages/ai.** There is no coverage config today. Add to `packages/ai/package.json`:
- script `"test:cov": "jest --coverage"`,
- `jest.collectCoverageFrom`: `["src/**/*.ts", "!src/**/*.spec.ts", "!src/index.ts", "!src/evals/run.ts", "!src/content/generate-breed-guides.ts"]`,
- `jest.coverageDirectory: "<rootDir>/coverage"`.

Run `pnpm --filter @pawcareright/ai test:cov --coverageThreshold='{}'` (or simply `jest --coverage`
before adding the threshold) purely to **measure**. Record the four global numbers.

**2c — set the ai threshold from the measurement.**
- If all four measured metrics clear `80/80/80/70` → write exactly
  `"global": { "statements": 80, "lines": 80, "functions": 80, "branches": 70 }` (mirrors api;
  no number is invented above what is measured, none is tuned down to fit).
- If a metric misses: first check whether the miss is concentrated in a *non-product entrypoint*
  (a CLI/generator/harness runner). Excluding such a file from `collectCoverageFrom` is legitimate
  **only** with a one-line justification comment naming the file and why it has no unit surface.
  Re-measure after any exclusion.
- If it still misses, use the bounded allowance: add targeted specs for the named uncovered modules
  and re-measure.
- If it *still* misses, STOP: write `loop/plans/T098.blocked.md` stating the measured number, what
  was tried, and that lowering the bar was refused. Do not ship an 80 that is not real, and do not
  ship a 75 dressed as a gate.

The four exclusion globs above are a **decision** (D3) — see Risks.

### Step 5 — Docket 2: the `dynamic-type.test.tsx` flake (root-cause hunt, no masking)

**Primary hypothesis to test first (do not fix before reproducing something).**
In `apps/mobile/__tests__/dynamic-type.test.tsx`, the home / check-result / paywall tests call
`await render(...)` — which is *not* an async gate; `render` returns synchronously — and then
immediately walk `toJSON()`. The home and chat screens fetch through a **real** `QueryClientProvider`
answered by the mocked `apiClient.get`, so the tree walked at assertion time is whichever of
{loading skeleton, loaded content} happens to be committed at that microtask. The chat describes
gate on `await findByTestId(...)`; home/check/paywall do not. Under full-suite parallel load the
scheduling shifts, so a *different tree* gets asserted — which can flip `maxFontSizeNodes(...).length
> 0`, `allNodes.length > 10` or `fixedHeightTextContainers(...)` (a skeleton block may legitimately
carry `h-…` classes).

**Reproduction experiment (run it, record the output):** temporarily make the mocked
`apiClient.get` resolve on a later tick (e.g. `await new Promise((r) => setImmediate(r))` before
resolving) and run the file. If any assertion changes result, the hypothesis is **confirmed** —
record the exact failing assertion in `docs/qa/regression-gate.md`. Revert the experiment.

**Fix (only these two, both strengthenings, neither weakens an assertion):**
1. Add an explicit settled-tree gate to every test that currently has none —
   `await screen.findByTestId("home-header")` (home), `"check-result-screen"` (check result),
   `"paywall-screen"` (paywall) — *before* collecting nodes, and re-read `toJSON()` after it.
2. In the two describes that install `mockedGet.mockImplementation`, call `mockedGet.mockReset()`
   before installing it. `jest.clearAllMocks()` clears calls but **not** queued
   `mockImplementationOnce` bodies — the exact T094-F2 root-cause family. `mockReset()` removes them.

**Explicitly forbidden here:** raising a jest/RNTL timeout, adding `retry`, adding `jest.retryTimes`,
relaxing a count floor, or deleting/`skip`ping any test. If the reproduction experiment produces
nothing and 3× full mobile runs (Step 11) are green, apply fixes 1 and 2 anyway as determinism
hardening and say so honestly in the doc: **"root cause not reproduced; the nondeterminism removed
here is a proven structural race, and the observed flake remains UNCONFIRMED."** Do not claim a fix
you did not demonstrate.

## Risks & the decisions the planner made (scrutinize these)

**D1 — "3 consecutive full CI runs" is satisfied by 3 local full-gate runs, explicitly labelled.**
*Risk:* a reader could mistake local evidence for CI evidence. *Mitigation:* H1's verbatim statement
is required in the doc, the journal and the M9 readiness section, and the real-CI requirement is
carried as **OPEN**. *Alternative rejected:* claiming CI runs (fabrication) or blocking the card
(the other 90% of the work is real and M9 would stall on an environment limitation).

**D2 — the coverage gate is a `pnpm test:cov` step inside the existing `build` job, not a new job.**
*Rationale:* the api coverage run needs postgres + redis + MinIO, all already provisioned there;
a second job would duplicate the whole services block (drift hazard) and double the infra.
*Risk:* it lengthens the critical path by re-running api + ai instrumented, and it is less visible as
a named required check than a standalone job. *If the checker prefers a named job,* that is a
one-block change and the pin in `coverage-gate.spec.ts` adapts trivially.

**D3 — api coverage scope stays `src/**/*.service.ts`; ai excludes `index.ts`, `evals/run.ts`,
`content/generate-breed-guides.ts`.** *Rationale:* CLAUDE §6 says "≥80% coverage on services" and the
card says "≥80% api services" — the existing glob is the literal reading, and it was already in force
via `test:cov`. The ai exclusions are barrel/CLI entrypoints with no unit surface. *Risk:* the api
glob excludes processors/guards (a known T040-era note, journal line 480) and the ai exclusions could
be read as scope-shopping. *Mitigation:* every exclusion is named with a reason in
`docs/qa/regression-gate.md`, and the measured global numbers are published so the scope is
auditable. Widening the api glob is deliberately **not** attempted — it risks a red-born gate, which
H2 forbids, and it is scope creep on a stabilize card.

**D4 — `test:cov` is `cache: false`.** *Risk:* slower runs. *Rationale:* a cached green makes the
"three cold consecutive runs" evidence meaningless, and coverage is exactly the kind of gate where a
stale cache hit is dangerous. Precedent: `test:ai-evals` is already `cache: false`.

**D5 — Playwright `retries: 0`.** *Risk:* a genuinely flaky E2E reddens CI. *Rationale:* this is the
flake-hunt card; shipping a retry would be self-defeating and would hide precisely what T098 exists
to find. If the smoke proves flaky, the honest response is to fix it or block — never to add retries.

**D6 — the E2E asserts derived copy (imports `buildLandingModel`/`buildFoodPageModel`/`strings`)
rather than hardcoded strings.** *Risk:* an E2E that imports the same model the page renders could be
accused of tautology. *Mitigation:* the E2E's value is the *end-to-end path* (real `next build` →
`next start` → real HTTP → real DOM), not the string values; the string values are already unit-pinned
by `render.spec.tsx` and `strings-detector-lint.spec.ts`. Hardcoding copy here would violate CLAUDE §6
and create a second source of truth. MU9–MU11 prove the assertions are not vacuous.

**D7 — T095 F5 is resolved by correcting the documentation, not by flipping `aggregationMethod`.**
*Risk:* the shipped gate remains best-of-3, which is weaker than the prose implied. *Rationale:* the
T095 checker's own fresh run put the landing representative at **exactly 0.90**; flipping to median
would put a required gate on the line, and the only two exits from the resulting flake are a perf fix
(out of scope) or a lowered threshold (categorically forbidden). Doc-to-reality reconciliation plus
9b's config pin is the honest, non-weakening move. This decision is explicitly flagged for the
checker to overrule if it disagrees.

**D8 — the `dynamic-type` fix may end up applied without a reproduced failure.** *Risk:* claiming a
flake is "fixed" when only a structural race was removed. *Mitigation:* Step 5 mandates the exact
honest wording ("root cause not reproduced; … the observed flake remains UNCONFIRMED") and forbids
every masking remedy (timeouts, retries, skips, relaxed floors).

**D9 — `@playwright/test` is a new dependency.** *Risk:* CLAUDE §2 rule 7. *Mitigation:* it is
named by the card and locked by CLAUDE §3; the justification line plus the resolved version and the
lockfile resolution-count delta go in the journal. It is a devDependency of `apps/web` only and is
never imported by product code. Secondary risk: the pinned chromium revision may not match
`/opt/pw-browsers/chromium-1194`, forcing a network download — Step 10b handles both branches and
requires recording which one was used.

**D10 — renaming two `a11y-sweep` test titles.** *Risk:* rule 4 is the doc↔test contract; a rename
that misses a `[AUTO]` tag turns it red. *Mitigation:* that is the desired behaviour — the rename and
the doc edit ship together and rule 4 must be green at the end, which is itself the proof they agree.
No assertion body is touched.
