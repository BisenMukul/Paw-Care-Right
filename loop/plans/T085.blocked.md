## Why this blocks T085 rather than being worked around

The plan is explicit, and the orchestrator's dispatch instructions reinforced it: step 0 "runs
FIRST" and "if it trips, STOP and report rather than special-casing." Per CLAUDE.md §7 and
PRODUCT_SPEC.md §5, a public SEO page that tells a searcher a human medication is "usually not a
concern" / "Usually fine" for their dog or cat is a fail-*downward* verdict on a `human-med`
category row — exactly the class of defect the tripwire exists to catch before 466 pages are
statically generated and shipped. This is a dataset-content question (is `safe` the correct
verdict for a stray antacid tablet, or should it be `caution`?), not a page-rendering question, so
it is out of scope for T085's executor to adjudicate or silently patch.

The plan is unambiguous that fixing this is **T105**'s remit ("packages/data/**... dataset is
read-only input — if a verdict looks wrong, that is T105, not T085"), and forbids editing
`packages/data/**` from this task's file list. No dataset edit was made.
