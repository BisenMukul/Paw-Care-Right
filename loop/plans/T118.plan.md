## 1. Design decisions (each one is deliberate; scrutinise them)

**D1 — Two dedicated jobs, not one job with two steps, not steps inside `build`.**
New jobs `safety-vet-disclaimer` and `safety-emergency-interstitial`. Together with the existing `ai-evals`, both publish jobs' `needs:` then names **exactly three** safety checks — which is the AC's literal wording ("the three named required checks on both publish jobs"). Rationale: in GitHub Actions a *check* is a **job**; `needs:` cannot reference a step, and branch protection cannot require a step. Rejected alternatives: (a) one `ota-safety-gates` job with two named steps → only **one** new name in `needs:`, and two of the three "named required checks" would be un-nameable in branch protection; (b) steps inside `build` → zero new names, no independent check at all; (c) a third job re-running `pnpm test:ai-evals` → duplicates an existing job's whole cost for nothing. Accepted cost: two extra runners per CI run (each ~1 `pnpm i --frozen-lockfile`), and the two suite sets now execute **twice** per run (once inside `build`'s `pnpm test`, once as their own check). That duplication is the same trade T098 accepted for `test:cov` (`ci.yml:102-110`) and is the price of the §8.2 mandate "required-green **for the publish job specifically**".

**D2 — No `name:` key on the new jobs**, so the GitHub check name equals the job key exactly (every other job in this workflow follows that convention). Runbook §18 lists those exact strings for branch protection.

**D3 — No job-level `if:` on the new jobs.** They must run on `pull_request`, `push` and `workflow_dispatch`. This is the T116 `mobile-fingerprint` trap in reverse: a job that is in `needs:` **and** event-scoped would be *skipped* on push-to-main, which skips the dependent publish job forever. A dedicated assertion pins this (test T5).

**D4 — Suite invocation is `pnpm --filter @bombaypetcompany/mobile exec jest --ci <explicit test paths>`.** No new root script, no `turbo.json` task, no `package.json` edit (fewest possible manifest edits; zero new deps per CLAUDE §2 rule 7). `--ci` is **load-bearing**: without it jest *writes* a missing snapshot and passes; with it a missing/new snapshot fails — i.e. a deleted `<VetDisclaimer/>` snapshot cannot self-heal inside the gate. `pnpm --filter <pkg> exec` runs with cwd = the package dir (verified empirically for `@bombaypetcompany/web`/lhci, see `ci.yml:253-255`), so the paths are `__tests__/…` relative to `apps/mobile`. If jest's positional patterns matched nothing it exits **1** ("No tests found") — fail-loud, not silently green.

**D5 — Suite membership (pinned twice: in ci.yml and in the config test).**

`safety-vet-disclaimer` (the "`<VetDisclaimer/>` snapshot suite"):
- `__tests__/check-result-snapshot.test.tsx` — every urgency tier + FALLBACK + redFlag snapshot, each asserting `getByTestId("vet-disclaimer")` (13 disclaimer nodes in its `.snap`)
- `__tests__/chat-screen-snapshot.test.tsx` — chat result snapshot + disclaimer testID (`:96`)
- `__tests__/breed-guide-sections.test.tsx` — breed guide snapshot + disclaimer (2 nodes in its `.snap`)
- `__tests__/disclaimer-placement-scan.test.ts` — T097's centralization inventory: the *set* of screens rendering `<VetDisclaimer/>` must equal the pinned list, both directions

`safety-emergency-interstitial` (the "Emergency interstitial flow tests"):
- `__tests__/emergency-interstitial.test.tsx` — renders **before** any AI content, acknowledge-gating/back-block, region hotline + fallback, fail-upward on unknown payloadKey, still reachable with the `checks` kill switch off
- `__tests__/paywall-emergency-safety.test.tsx` — no paywall anywhere on the `/check/emergency/[checkId]` path
- `__tests__/check-submission.test.tsx` — the flow's **entry**: a redFlag response `router.replace`s to `/check/emergency/[checkId]` (`:73`)

**D6 — "Loop is forbidden from prod publishes" gets two proofs, not one.** The card's parenthetical defines the AC ("assert job has no automated trigger") → that is the trigger audit (step 8). Beyond it, one bounded scan test asserts that **no loop-writable automation surface** invokes a production publish or a workflow dispatch (step 10). Scanned inventory is explicit: `scripts/*.{js,sh}`, `.claude/hooks/*.sh`, `apps/mobile/scripts/*`, root `package.json`'s `scripts` values, `turbo.json`. **`docs/**`, `README.md` and `loop/journal.md` are deliberately excluded** — the runbook *must* document the human dispatch procedure, and forbidding the string there would forbid the documentation this same card adds. This is scope beyond the card's parenthetical: see R5; the checker may reject it without touching AC compliance.

**D7 — The T117 Finding 3 fold-in is one new mobile test file and zero source changes.** `use-push-registration.ts` is **not** modified; the test pins its current payload shape. ## 7. Risk register (top 5 — every design decision is listed here for the checker to scrutinise)

**R1 — D1's CI cost is real and doubles two suite runs.** Two extra runners per CI run, each paying a full `pnpm i --frozen-lockfile` (which also builds `packages/*` via mobile's postinstall), and the seven suites now execute twice per run. Judged acceptable for an S card because it is the *only* shape in which the three checks are independently nameable in `needs:` **and** in branch protection, and because §8.2 demands "required-green for the publish job specifically". A cheaper single-job variant (one job, two named steps) is the documented fallback if the checker rules D1 over-built — it costs the literal reading of AC1.

**R2 — jest positional patterns are regexes and silently tolerate a partial match set.** If a suite is renamed and ci.yml is not updated, jest runs the remaining suites and passes. Mitigated by T3 (both-direction path↔body equality) + T4 (`existsSync`). Residual, disclosed: nothing here stops a suite from being *internally* gutted (e.g. deleting its `getByTestId("vet-disclaimer")` line). `disclaimer-placement-scan.test.ts` is in the set precisely because it is the hardest of the four to gut silently, but an edit to a snapshot suite's own body is out of this card's reach.

**R3 — a job-level `if:` on either new job would break the push-to-main preview publish permanently** (the T116 `mobile-fingerprint` trap: a skipped `needs:` target skips the dependent job). The existing "every exempted job is genuinely event-scoped" test does **not** catch a newly *event-scoped* job that is *included* in `needs:` — hence T5 as a distinct assertion. If the checker finds a stronger formulation (deriving the skip risk from the workflow graph), take it.

**R4 — `pnpm --filter … exec jest` cwd and `--ci` semantics are assumptions verified only locally.** cwd = package dir is inferred from the lhci precedent's own in-file comment plus local execution; `--ci` preventing new-snapshot writes is documented jest behaviour. Both are proved by running the exact commands locally (§6), and a wrong cwd fails loud (jest exits 1, "No tests found") rather than silently green. GitHub's own YAML parser remains the closing evidence on first push (T116 R1 carry-forward).

**R5 — D6 (the loop-forbidden automation scan) is scope beyond the card's parenthetical, and its exclusions are a judgement call.** The card defines the loop-forbidden proof as the trigger audit; the scan is additive. Its inventory deliberately excludes `docs/**`, `README.md` and `loop/journal.md` because those legitimately document the human dispatch procedure — so it can catch "an automated surface in this repo contains the command", not "a human pasted it from the runbook". If the checker judges this out of scope for an S card, deleting T12/T13 costs no AC. Related residual, founder-owned: config cannot prove the loop's *token* lacks `actions:write`.

*(R6, minor)* — `docs/release-runbook.md` carries file-wide invariants (no line with both `10%` and `50%`; `SECRET_PATTERNS`) that a carelessly worded §18 would break; T19 pins them and the existing `:258` test must be re-run unmodified.
