## 2. Design decisions (each is also a Risk entry — scrutinise)

- **D1 — custom snake_case assignment/exposure events, not PostHog's `$feature_flag_called`.** Forced, not stylistic: `packages/analytics/src/store-privacy-doc.spec.ts:64` parses event names out of `events.ts` with `/^ {2}(\w+): \{$/` and set-equality-compares both directions against the doc, so a `"$feature_flag_called"` key would be invisible to the source side and fail the suite; `AnalyticsEventName` is also the typed union the whole transport is generic over. PostHog experiments natively support a **custom exposure event**, so the console side stays wire-compatible. Names: `paywall_experiment_assigned`, `paywall_experiment_exposed`.
- **D2 — do NOT add a variant property to `trial_start`.** Attribution is person-level (same `distinct_id`, table above), so PostHog attributes the goal metric per arm from the exposure event. The alternative (recompute the variant server-side inside `rc-webhook.service.ts`) would silently mis-attribute every conversion if `PAYWALL_VARIANT` were flipped mid-run, and would drag the api suite in. Rejected; reason recorded in the experiment doc.
- **D3 — assignment ≠ exposure.** `paywall_experiment_assigned` = enrolment, fired **once per app session** from the root layout when the resolved variant is first observed (no extra network: it re-uses the `["app-config"]` query already fetched at launch by `useUpgradeState`). `paywall_experiment_exposed` = the user actually saw an arm, fired **on paywall mount, once per rendered variant**. Exposure is the metric's denominator.
- **D4 — min-sample guard = drift-guarded constant + documented no-peek rule, not runtime code.** Nothing in this repo can read PostHog counts (no read API, no keys), so an "enforced" guard would be theatre. `PAYWALL_EXPERIMENT_MIN_SAMPLE_PER_ARM = 900` exposed users per arm, from the standard 80 %-power / α = 0.05 two-sided approximation `n = 16·p̄(1−p̄)/δ²` with baseline `p = 0.08` (SPEC §8 target ≥ 8 %), target `0.12`, `p̄ = 0.10`, `δ = 0.04` → `16 × 0.09 / 0.0016 = 900`. The doc states formula and number; the guard spec asserts they agree.
- **D5 — variant A copy stays byte-identical.** A is the control; only B gains new trial framing. Consequence: only the variant-B snapshot block changes, keeping the review surface minimal.
- **D6 — no new PostHog provisioning code.** The experiment is created in the console by the founder. `posthog-insights.ts` / `docs/observability-dashboards.md` are untouched: `observability-doc.spec.ts:34,82-96` pins exactly three tracked events and fails on any un-allowlisted snake_case token in that doc — the same reason T117's `ota_*` events never appeared there.

**Non-goals (do not do):** no `/config` or `packages/types` change; no api/Nest change; no `posthog-insights.ts` / `sentry-alerts.ts` / `docs/observability-dashboards.md` change; no new dependency; no `trial_start` shape change; no i18n work (T110); no second experiment framework; no `loop/journal.md` / `loop/loop-state.json` edit; no commit.
