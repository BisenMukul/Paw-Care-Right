# Plan — T083: Mobile chat UI ("Ask Paw Care Right +")

## Objective (from card)
Build the mobile chat screen against T081/T082's SSE endpoint: active-pet badge, streaming bubbles,
quick prompts, a **persistent non-dismissible `<VetDisclaimer/>` footer**, a nudge frame rendered as a
tappable card into the existing check intake flow, and retry on **transport** stream drop.
**Accept:** component tests for stream render, drop-retry, and nudge-card→check-flow routing.

---

## Safety statement (PRODUCT_SPEC §5 / CLAUDE.md §7 — LOAD-BEARING, read before step 1)

1. **No server safety surface is touched.** This task adds **zero** files under `apps/api/**`,
   `packages/ai/**`, `packages/types/**` or `apps/api/prisma/**`. The output gate, the overlap scan,
   `SAFE_FALLBACK_CHAT_MESSAGE`, the incident log, the nudge detector, quota, entitlement, red-flag
   rules and hotlines are all consumed as-is and are **not on the file list**.
2. **The disclaimer is structural, not conditional.** `<VetDisclaimer/>` renders in the chat screen's
   fixed footer region on **every** state (loading, empty, streaming, error, offline, safe-fallback,
   402-locked, 402-quota). It is not inside any conditional branch, has no dismiss affordance, and is
   pinned by a snapshot **and** a per-state assertion loop (AC-S1).
3. **Retry is for TRANSPORT only — never for safety outcomes.** Two terminal states are modelled
   *separately and explicitly* (D7):
   - `dropped` — the byte source ended (or threw) **without** a `done` frame ⇒ the transport failed
     mid-stream ⇒ a **Retry** affordance is offered.
   - `safeFallback` — a `done` frame arrived with `status: "SAFE_FALLBACK"` ⇒ the server made a
     **safety decision**. The screen renders the safe-fallback notice and **renders NO retry button,
     no regenerate, no "try again" for that message.** Asserted positively (`queryByTestId(...)` is
     `null`) and mutation-proven (M3). A `SAFE_FALLBACK` answer is *the answer*; re-asking is the
     user typing a new message, which is a new request through the same gate.
4. **Fail upward on every unknown.** Any frame that fails its `packages/types` Zod schema, any
   unknown event name, and any non-`done` termination is treated as a stream failure — never
   guessed, never silently retried, never rendered as assistant content (D4).
5. **No "diagnosis" vocabulary, no dosing, no drug names, no outcome claims** in any new string.
   Enforced by a dedicated tone scan over the new `strings.chat` subtree
   (`chat-strings-tone.test.ts`), modelled on `craft2-strings-tone.test.ts`, including its
   non-vacuity proof.
6. **The nudge card escalates, never de-escalates.** It routes into the EXISTING `/check/[category]`
   intake (which owns the deterministic red-flag → emergency path). It never renders AI content, never
   suppresses or delays anything, and appears **before** the assistant bubble in reading order —
   mirroring the server, which emits `nudge` before any `chunk`.
7. **Premium gating never gates safety.** The chat screen is the ONLY thing gated. It contains no
   emergency interstitial, no hotline, no red-flag surface, and its 402 states do not touch
   `/check/**`, `/paywall`'s emergency-safety invariants, or `usePaywallOnboardingTrigger` (which
   this task does not import).
8. **No SAFETY-ESCALATION.** The card strengthens §5 surfaces (adds a disclaimer + an escalation
   card + a fail-upward stream client) and is implementable exactly as written.

## Key decisions (each is a design choice — restated with risks at the end)

- **D1 — SSE mechanism: `expo/fetch` + `ReadableStream` reader + `TextDecoder`, behind a tiny in-repo
  transport interface; SSE framing parsed by a NEW pure parser in `packages/api-client`. NO new
  dependency.**
  Verified in-tree: `expo@57.0.6` ships `expo/fetch` (`node_modules/.pnpm/expo@57.0.6…/expo/fetch.js`
  → `build/winter/fetch/index`), whose `FetchResponse` declares
  `get body(): ReadableStream<Uint8Array> | null` (`build/winter/fetch/FetchResponse.d.ts:20`) — i.e.
  **real incremental body streaming in React Native**, unlike RN's classic `fetch`. `TextDecoder` and
  `TextDecoderStream` are installed as globals by Expo's winter runtime
  (`expo/src/winter/runtime.native.ts:15,17`). `expo` is already a pinned dependency of
  `apps/mobile` (`package.json:25`), so this is **not** a new package (§2 rule 7 satisfied; a one-line
  journal note still required, see step 12).
  XMLHttpRequest `onprogress` was considered and rejected: it needs manual byte-offset bookkeeping over
  a growing `responseText`, has no abort-clean semantics we don't already get from `AbortController`,
  and would be untestable without mocking a native module. `expo/fetch` gives a WHATWG stream we can
  drive with a scripted async generator in tests.
  **Graceful degradation (fail-safe, not fail-open):** if `response.body` is `null` (any runtime
  without native streaming, e.g. Expo Go), the transport falls back to awaiting `response.text()` and
  yielding it as ONE chunk. The parser then emits every frame at once, so the UI renders the complete,
  correctly-ordered answer non-incrementally. It never breaks, never drops frames, never invents text.
  **Executor verification step (do this FIRST, step 1):** confirm `import { fetch } from "expo/fetch"`
  typechecks from `apps/mobile`. If `expo/fetch`'s exported `fetch` is not structurally assignable to
  the plan's `SseTransport` (its declared input is `string | URL | FetchRequestLike`, its init is
  `FetchRequestInit`), adapt **inside** `apps/mobile/src/chat/expo-sse-transport.ts` by calling it with
  a plain string URL + a plain object init — do **not** widen the api-client type, do **not** add
  `as any`/`@ts-ignore`. If it cannot be made to typecheck without a cast, STOP and write
  `loop/plans/T083.blocked.md`.

- **D2 — The generic SSE machinery lives in `packages/api-client`; the chat *semantics* live in
  `apps/mobile/src/chat/`.**
  `packages/api-client` gets: a pure frame parser (`sse.ts`) and a transport-agnostic runner
  (`stream.ts`) exposed as a new optional `ApiClient.streamSse(...)`. It knows about HTTP status,
  headers, `ApiError` normalization and `event:`/`data:` framing — **nothing** about `start`/`nudge`/
  `chunk`/`done`. The chat state machine (frame → typed event via `packages/types` Zod schemas,
  terminal-status classification, drop detection) lives in `apps/mobile/src/chat/chat-stream.ts`.
  Rationale: `packages/api-client` is imported by `apps/web`, which has no chat feature and must not
  gain chat types; and the parser is genuinely reusable/unit-testable in the package's existing
  node/ts-jest suite against recorded frame fixtures (the brief's requirement).

- **D3 — `streamSse` reuses `createApiClient`'s auth + single-flight refresh, and normalizes non-200
  bodies through the existing `normalizeError`.** The 402/404 envelopes T081 guarantees are written
  **before** any SSE header, so a non-200 has a complete JSON body and maps to exactly the same
  `ApiError` (`PAYMENT_REQUIRED`/`NOT_FOUND`) the rest of the app already branches on. A 401 is also
  strictly pre-header (auth guard) with **no** persisted user row and **no** quota consumed, so a
  single refresh-then-retry is side-effect-free and mirrors `request()` exactly. Without this, chat
  would be the only screen that hard-signs-out on a merely stale token.

- **D4 — Every frame payload is validated with the `packages/types` Zod schema for its event name; an
  unknown event name is ignored, an INVALID payload aborts the stream as a failure.**
  `chatStartEventSchema` / `chatNudgeEventSchema` / `chatChunkEventSchema` / `chatDoneEventSchema`
  already exist (`packages/types/src/chat.ts:46-76`) — never hand-write a duplicate interface (CLAUDE
  §6 Shared). Ignoring *unknown* names is forward-compatible; failing on a *malformed known* payload is
  §5 rule 2 (fail upward, never guess).

- **D5 — Thread lifecycle: ONE thread per pet per app session, created lazily on the first send, held
  in a NON-persisted Zustand store keyed by petId.** T081 shipped no thread-list and no
  message-history endpoint, so server-side replay is impossible; the DB thread is nonetheless the
  server's history context (`gatherHistory`), so the client must keep using the SAME threadId for the
  whole conversation or the model loses continuity. Non-persisted (mirrors `premium-store.ts`) so a
  cold start begins a clean thread — and so no assistant text is ever written to device storage.
  Switching the active pet switches to that pet's thread/transcript (creating one on next send).

- **D6 — Thread creation is a plain `apiClient.post` inside the send orchestration, NOT a
  `useMutation`.** The global 402 upsell interceptor is a `MutationCache.onError` hook
  (`apps/mobile/src/api/query.ts:26-32`); routing thread creation through it would pop the global
  `<UpsellSheet/>` **on top of** this screen's own 402 state — the exact double-UI the checks flow
  avoids with `meta.skipUpsell`. Keeping it off the mutation cache means chat has exactly ONE
  premium UI, owned by the screen. (Same shape as `useCheckSubmission`'s bespoke `quota` state.)

- **D7 — Two distinct terminal failure states, never merged: `dropped` (retryable) vs `safeFallback`
  (NOT retryable).** See Safety statement 3. Also distinct: `error` (a pre-stream `ApiError` that is
  not 402 — retryable) and `blocked402` (premium/quota — not retryable, routes to paywall or shows
  honest quota copy).

- **D8 — 402 copy is chosen from `usePremiumStore().status`, not from the error message.** Both
  chat 402s (`FREE` tier feature-lock and fair-use quota) return `PAYMENT_REQUIRED` with no
  machine-readable discriminator. `status === "entitled"` ⇒ the caller pays ⇒ this is the monthly
  fair-use limit ⇒ honest "you've reached this month's limit… you can still reach a vet anytime" with
  **no** upgrade CTA. Otherwise ⇒ feature lock ⇒ "See plans" → `/paywall?source=chat`. Never parse
  server prose (not i18n-able, not a contract).

- **D9 — Placement: a PUSHED screen at `app/chat/index.tsx`, reached from the home tab's quick-actions
  grid, NOT a fifth tab.** The tab bar is a locked 4-item set (`(tabs)/_layout.tsx`) and adding a tab
  would restructure the app's primary navigation — scope creep on a card that says "Chat screen".
  `QuickActionsGrid` already has a `wide`-bucket 4-per-row branch and takes explicit `on*` props, so a
  5th tile is additive and mechanical.

- **D10 — Quick prompts PREFILL the composer; they do not deep-link.** The card says quick prompts
  "routing to F3" — **F3 (Food & Toxin Safety) has no mobile surface and no API surface in this repo**
  (verified: no `apps/api/src/**/food*`, no `toxin` match anywhere in `apps/api/src`, no
  food/toxin screen in `apps/mobile/app/**`, and PHASES has no mobile-F3 card; T035 shipped
  dataset+service only, T085 is the web surface). Deep-linking to a non-existent route would be a
  dead end (design-system §7.5 "no flow dead-ends"). So "Is this food safe?" prefills the composer and
  the question is answered by chat itself, which is the F3 *capability* reaching the user. This
  divergence from a literal reading of the card is flagged as **R1** for the checker.

- **D11 — Auto-scroll pins to the bottom while streaming ONLY while the user has not scrolled away.**
  A `userPinnedToBottom` ref flipped by `onScroll` (distance-from-bottom threshold) gates the
  `scrollToEnd` call. Tested as a pure helper (`isNearBottom`) rather than by simulating native scroll
  metrics.

```ts
// packages/api-client/src/sse.ts — pure, mirrors apps/api/src/chat/sse-writer.ts:38
//   res.write(`event: ${event}\ndata: ${JSON.stringify(data)}\n\n`)
export interface SseFrame {
  /** The `event:` field value; "message" when the frame carried no event line (SSE default). */
  event: string;
  /** The concatenation of all `data:` lines, joined with "\n" (raw text, NOT parsed). */
  data: string;
}
export interface SseFrameParser {
  /** Feeds one decoded text chunk; returns every COMPLETE frame it now has. Partial tails are retained. */
  push(text: string): SseFrame[];
  /** Returns a final frame if a complete-but-unterminated block remains; clears state. */
  flush(): SseFrame[];
}
export function createSseFrameParser(): SseFrameParser;
// Requirements: handles a frame split across ANY number of chunks; multiple frames in one chunk;
// "\r\n" as well as "\n"; ignores comment lines starting with ":"; ignores unknown field names
// (id:, retry:); tolerates "data:x" and "data: x" (one optional leading space stripped).

// packages/api-client/src/stream.ts — transport-agnostic
export interface SseTransportResponse {
  status: number;
  getHeader(name: string): string | null;   // case-insensitive
  /** Decoded UTF-8 text chunks, in order. May yield the whole body as one chunk. */
  chunks: AsyncIterable<string>;
}
export interface SseTransportRequest {
  url: string;
  method: "POST";
  headers: Record<string, string>;
  body: string;
  signal?: AbortSignal;
}
export type SseTransport = (req: SseTransportRequest) => Promise<SseTransportResponse>;

export interface StreamSseOptions {
  onFrame: (frame: SseFrame) => void;
  /** Called once, after status/headers are known and status is 2xx (quota headers land here). */
  onOpen?: (headers: { get(name: string): string | null }) => void;
  signal?: AbortSignal;
}
/** Resolves when the byte source ends normally. Throws `ApiError` on non-2xx (body normalized via
 *  `normalizeError`) and on transport failure (`normalizeNetworkError`). It NEVER interprets frame
 *  semantics and NEVER retries. */
export function streamSseRequest(
  transport: SseTransport,
  req: SseTransportRequest,
  options: StreamSseOptions,
): Promise<void>;

// packages/api-client/src/client.ts — additive
export interface ApiClientConfig {
  /* …unchanged… */
  streamTransport?: SseTransport;
}
export interface ApiClient {
  /* …unchanged… */
  /** Throws if no `streamTransport` was configured. 401 ⇒ one single-flighted refresh + one retry. */
  streamSse(path: string, body: unknown, options: StreamSseOptions): Promise<void>;
}

// apps/mobile/src/chat/use-chat-stream.ts
export type ChatStreamState =
  | "idle" | "sending" | "streaming"
  | "dropped"      // transport ended without `done`  -> RETRY OFFERED
  | "safeFallback" // done.status === "SAFE_FALLBACK" -> NO RETRY (safety, D7)
  | "error"        // non-402 ApiError before/around the stream -> RETRY OFFERED
  | "blocked402"   // premium lock or fair-use quota  -> NO RETRY (D8)
  | "offline";     // send blocked, never attempted
export interface UseChatStream {
  state: ChatStreamState;
  messages: ChatUiMessage[];
  send: (text: string) => void;
  /** No-op unless state is "dropped" or "error". Re-sends the last USER message text. */
  retry: () => void;
}
export function useChatStream(petId: string | undefined): UseChatStream;
```

**Reducer rules (pin exactly).** `send(text)`:
offline ⇒ `offline`, no network call · else append the USER bubble **immediately**, set `sending` ·
ensure a threadId (`POST /v1/chat/threads {petId}` if absent — D6) · append an EMPTY assistant bubble
with `status:"streaming"` · `apiClient.streamSse("/v1/chat/threads/{id}/messages", {content}, …)`.
Frames: `start` → record `assistantMessageId`, set `streaming` · `nudge` → set the assistant bubble's
`nudgeCategory` (renders **above** the bubble) · `chunk` → append `value.text` to the assistant bubble
(append-only; **never reorder by `seq`, but DO assert monotonic `seq` in tests**) · `done` → set
`status` from `value.status` (`"OK"`→`ok`, `"SAFE_FALLBACK"`→`safeFallback`) and set the hook state to
`idle` or `safeFallback` accordingly; mark the stream terminated · `invalid` → abort, treat as
`dropped`.
Termination without a `done` frame (resolve or throw) ⇒ `dropped`.
`ApiError` with `code === "PAYMENT_REQUIRED"` ⇒ `blocked402`; any other `ApiError` ⇒ `error`.
`retry()` in `dropped`/`error`: `removeMessage(assistantId)` (discard the partial bubble — it is not a
truthful record of a completed answer) and re-run `send(lastUserText)` **on the same thread**, without
re-appending the user bubble. In `safeFallback`/`blocked402`/`offline`/`streaming` it is a **no-op**.

**Screen states (all six must be reachable and asserted).** `loading` (active pet still loading →
`Skeleton`) · `empty` (a pet, no messages → quick prompts + inviting copy per §7.6, **no** "No data")
· `error` · `offline` (banner + composer disabled, copy mirrors `strings.check.offlineBanner` tone) ·
`blocked402` (D8 two-copy branch) · content/streaming. **`<VetDisclaimer/>` renders in the footer in
ALL of them.**

Each mutation below is argued **non-vacuous**: it changes observable behaviour on a path a named test
exercises. (T082's review, Finding 1, caught a `= 0` mutation that was a JS no-op via `slice(-0)`;
none of these use that shape, and each states why it cannot be a no-op.)

| # | Mutation | Why it CANNOT be a no-op | Must FAIL (exactly) |
|---|---|---|---|
| **M1** | In `sse.ts`, make `push()` return frames from the current chunk only, discarding the retained partial tail (`buffer = text` instead of `buffer += text`) | The split-frame fixtures deliver a frame across chunk boundaries; without carry-over the second half parses as a headless fragment and the frame is never emitted — strictly fewer frames | `sse.spec` "reassembles a frame split across N chunks", "retains an unterminated tail until flush()"; `chat-screen` "a frame split across transport chunks renders exactly once" |

## Risks & the decisions the planner made (for the checker)

- **R1 (D10) — "quick prompts … routing to F3" is implemented as composer prefill, not navigation.**
  There is no mobile or API F3 surface in this repo (verified by grep: no `apps/api/src/**/food*`, no
  `toxin`/`food-safety` match under `apps/api/src`, no food screen under `apps/mobile/app/**`; PHASES
  has no mobile-F3 card — T035 is dataset+service, T085 is the web pages). A deep link to a
  non-existent route is a dead end (design-system §7.5). **If the checker judges the card to require
  navigation, the correct resolution is a follow-up card for a mobile F3 screen, not a stub route.**
- **R2 (D1) — `expo/fetch` streaming is verified by TYPE and by Expo's documented winter runtime, not
  by a device run.** The plan's jest tests exercise the parser/runner/hook through an injected fake
  transport, so they prove the *consumption* logic but not the native byte delivery. Mitigations: the
  `body === null → text()` fallback means a runtime without native streaming still renders a complete
  answer; and step 1 makes the typecheck a gate. Residual: incrementality on device is unproven in CI
  (inherent — same class as T081's supertest-buffers-SSE risk, R9 there).
- **R3 (D3) — adding `streamSse` to the shared `ApiClient` touches a file `apps/web` also imports.**
  Mitigation: purely additive (one optional config field, one new method); every existing
  `client.spec.ts` case must pass unmodified, which is the behavioural-equivalence proof. `apps/web`
  passes no `streamTransport` and therefore cannot reach the new code path.
- **R4 (D5) — a non-persisted, session-scoped thread means a cold start loses the transcript.** This is
  a deliberate consequence of T081 shipping no history endpoint. It is also privacy-positive (no
  assistant text on device). If the founder wants durable history, it needs a server `GET
  /chat/threads/:id/messages` first — a new card.
- **R5 (D8) — inferring "quota exhausted" vs "feature locked" from `usePremiumStore`.** `status` can be
  `"unknown"` (Expo Go / not yet refreshed); `"unknown"` is treated as **not entitled** ⇒ the
  feature-lock copy with "See plans". That is the honest, non-blocking direction (it never claims the
  user hit a limit they didn't). A machine-readable discriminator on the API would be strictly better
  and is a candidate follow-up.
- **R6 (D7) — `retry()` discards the partially-streamed assistant bubble.** Alternative (keeping the
  partial text and appending the retry's output) would splice two different completions into one
  message, producing text no gate ever approved as a whole. Discarding is the fail-upward choice.
- **R7 (D9) — a 5th quick-action tile changes an existing home component.** The tile is structurally
  identical to its four siblings (same classes, same disabled handling, same stagger), and the `wide`
  bucket already renders 4-per-row so 5 tiles simply wrap. Risk: an existing home snapshot may
  re-record. **The executor must NOT silently update a snapshot** — if one changes, stop and report.
- **R8 — new-file test convention is unverified** (`__tests__/*.test.tsx` vs co-located `*.spec.ts`
  under `src/`). `apps/mobile/jest.config.js` sets only `preset: "jest-expo"`, and
  `src/storage/safe-storage.test.ts` exists alongside 149 files in `__tests__/`, so both plausibly
  collect. Step 1 resolves it empirically; the file list above must then be applied consistently.
- **R9 — auto-scroll is tested only through the pure `isNearBottom` helper**, not through real scroll
  metrics (RNTL cannot produce them). The wiring (`onScroll` → ref → `scrollToEnd`) is therefore
  covered by inspection, not assertion. Accepted: it is a comfort feature with no safety weight.
- **R10 — mobile resolves `@pawcareright/api-client` from `dist`.** Forgetting step 5 gives a stale
  module and a green suite that proves nothing. This is exactly the T082 R1 hazard; step 5 exists
  solely for it.
