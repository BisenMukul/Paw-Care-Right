# Plan — T089: Sentry everywhere + release tagging

## Objective (from card)
Init Sentry in api/web/mobile with `environment` + `release`, wire source-map upload into CI
(gated — CI must stay green without secrets), and add PII scrubbing so **no intake text, chat
content, pet data, emails, or tokens ever reach Sentry**. ACs: (1) forced test error appears with
the release tag — proven offline via a mock transport, journaled honestly; (2) scrubber unit test.

## Safety statement (PRODUCT_SPEC §5-adjacent)
- No §5 surface is touched: no prompts, no `<VetDisclaimer/>`, no emergency interstitial, no
  triage/rules/hotline code, no dosing-related string. `packages/ai` is not on the file list.
- PII scrubbing is privacy-adjacent safety: the scrubber **fails closed** — if it throws on a
  pathological event, `beforeSend` returns `null` and the event is DROPPED (losing telemetry is
  acceptable; leaking an owner's symptom description is not).
- Intake text/chat content are the §5-sensitive payloads: they travel in request bodies and could
  echo into validation-error messages and breadcrumbs. The scrubber removes request bodies
  structurally (not by key-matching) so a new endpoint can never leak by omission.
- No SAFETY-ESCALATION: this card only adds observability + a privacy control; nothing weakens
  disclaimers, escalation, or dosing prohibitions.

## Key decisions (minimum set — each restated under Risks)
- **D1 — One shared, pure scrubber + options factory in `packages/analytics/src/sentry/`.**
  Runtime-neutral (node/RN/browser): operates on a structural `SentryEventLike` type — **no
  `@sentry/*` import in the package** (zero new deps there). All three apps pass
  `beforeSend: scrubSentryEvent` from the same factory. Web gains a workspace dep on
  `@pawcareright/analytics` (workspace link, not a new external package).
- **D2 — Release format reconciliation (card "git sha" vs §1a `pawcareright@{version}+{updateId}`).**
  The §1a *shape* is kept everywhere: `buildSentryRelease(version, buildId)` →
  `pawcareright@{version}+{buildId}`. The `+{buildId}` slot is filled with the **git sha** for
  api/web (servers have no OTA updateId — the sha IS their build id) and, for mobile *at T089
  only*, with the build-time git sha (`EXPO_PUBLIC_GIT_SHA`, default `dev`) because
  `expo-updates` doesn't exist until T113; **T117 owns swapping the mobile slot to
  `Updates.updateId`** per OTA_UPDATES §7. No new scheme is invented; the card's "git sha" and
  §1a's shape are both satisfied.
- **D3 — Scrub algorithm: structural drops first, then a cycle-safe deep redaction walk.**
  Structural drops: `request.data` + `request.cookies` deleted wholesale; `request.headers`
  reduced to an allowlist {`host`, `user-agent`, `content-type`, `content-length`};
  `request.query_string` deleted and `request.url` truncated at `?` (tokens/OTPs ride in query
  params); `user` reduced to `{ id }` only (no email/ip/username — also `sendDefaultPii: false`
  in the factory); each breadcrumb's `data` reduced to allowlist {`method`, `status_code`,
  `category`, plus `url` truncated at `?`}. Then `redactDeep` walks every remaining string in the
  event (messages, exception values, breadcrumb messages, extra, contexts) with a `WeakSet`
  cycle guard, replacing email addresses, `Bearer <token>`, and JWT-shaped `eyJ...` substrings
  with `[REDACTED]`. Any internal throw ⇒ return `null` (drop event, fail closed).
- **D4 — Offline proof for AC1 (no staging DSN exists in this environment — be honest).**
  A real `@sentry/node` init in a jest spec with a **custom mock transport**: force
  `captureException` with planted markers (fake intake text in `request.data`, an email in the
  message), `flush()`, then assert the captured envelope (a) carries
  `release === buildSentryRelease(...)` matching `/^pawcareright@\d+\.\d+\.\d+\+.+$/` and the
  `environment` tag, and (b) contains **none** of the planted PII markers (scrubber provably ran
  inside a real SDK pipeline). Web/mobile assert the same shared factory output (release,
  environment, `beforeSend === scrubSentryEvent`, `sendDefaultPii: false`). The journal records
  this as the staging-run evidence **with the limitation stated explicitly**, and adds a founder
  to-do: "create Sentry projects, set real DSNs + SENTRY_AUTH_TOKEN, run one real forced-error
  smoke per platform." No fabricated staging claims.
- **D5 — Stub-safe by default, POSTHOG-style.** All DSN env keys default to `""`; the factory
  emits `enabled: dsn !== ""` and callers skip `init` entirely on empty DSN. Local dev, jest,
  and CI never hit the network and never need secrets. Mobile additionally lazy-`require`s
  `@sentry/react-native` inside `initMobileSentry()` behind the DSN check + try/catch, because
  the native module is absent in Expo Go/jest (MMKV precedent in the journal).
- **D6 — Version part of the release comes from env, defaulting to the current `0.0.0`:**
  api `APP_VERSION` (Zod, default `"0.0.0"`), web `NEXT_PUBLIC_APP_VERSION` (default
  `"0.0.0"`), mobile `getAppVersion()` (already exists). CI/deploy sets them later (T099 wires
  real versioning). No hardcoded duplicate of a package.json version.
- **D7 — CI upload gating: job-level `env: SENTRY_AUTH_TOKEN: ${{ secrets... }}` + step-level
  `if: env.SENTRY_AUTH_TOKEN != ''`** (secrets are not readable in `if:` directly). When absent,
  a skip-notice step (inverse condition) writes "Sentry source-map upload skipped — no
  SENTRY_AUTH_TOKEN secret" to `$GITHUB_STEP_SUMMARY`. CI stays green with zero secrets.
  API upload uses `getsentry/action-release` (sourcemaps input — no new npm dep); web upload is
  `withSentryConfig`'s built-in build-time upload, active only when the token env is present.
  **Mobile source maps are honestly out of CI's reach**: they ride the EAS build/update pipeline
  (config plugin added here does the wiring; actual upload happens in EAS jobs at T099/T116) —
  documented in the journal, not faked with a dead CI step.
- **D8 — API capture policy: only 5xx / non-`HttpException` errors go to Sentry** (4xx are
  expected client noise), tagged with `requestId` only — never the request object. The
  `captureException` call is try/catch-wrapped so the filter can never throw.
- **D9 — New dependencies (§2.7 journal justifications, all actively maintained, massive
  adoption, releases well within 6 months as of 2026-07):** `@sentry/node` (api),
  `@sentry/nextjs` (web), `@sentry/react-native` (mobile — the maintained successor to the
  deprecated `sentry-expo`, ships the official Expo config plugin). No `@sentry/cli` package
  dep (CI uses the official action).

## Interfaces/contracts (executor must match)
```ts
// packages/analytics/src/sentry/scrub.ts
export interface SentryEventLike {
  event_id?: string; message?: unknown; level?: string; release?: string; environment?: string;
  user?: { id?: string; email?: string; ip_address?: string; username?: string; [k: string]: unknown };
  request?: { url?: string; query_string?: unknown; data?: unknown; cookies?: unknown;
              headers?: Record<string, string>; [k: string]: unknown };
  breadcrumbs?: Array<{ category?: string; message?: string; data?: Record<string, unknown>;
                        [k: string]: unknown }>;
  exception?: unknown; extra?: Record<string, unknown>; contexts?: Record<string, unknown>;
  tags?: Record<string, unknown>; [k: string]: unknown;
}
export const REDACTED = "[REDACTED]";
export function scrubSentryEvent(event: SentryEventLike): SentryEventLike | null; // pure, never throws

// packages/analytics/src/sentry/options.ts
export function buildSentryRelease(version: string, buildId: string): string; // pawcareright@{v}+{id}
export interface BaseSentryOptions {
  dsn: string; environment: string; release: string; enabled: boolean;
  sendDefaultPii: false; tracesSampleRate: 0;
  beforeSend: (event: SentryEventLike) => SentryEventLike | null;
}
export function baseSentryOptions(input: { dsn: string; environment: string; release: string }): BaseSentryOptions;
```
- The api/web/mobile init sites spread `baseSentryOptions(...)` into the SDK's `init` — cast at
  the boundary via the SDK's own option type, never `any` (`beforeSend`'s structural type is
  assignable; if the SDK type fights, a single `satisfies`/adapter in the init file, not in the
  shared package).
- Error envelope `{ error: { code, message, requestId } }`, SSE contracts, Prisma schema,
  Swagger: **unchanged**. No migration (`prisma migrate status` still "up to date").
