# Plan — T081: Chat API (threads + SSE)

## Objective (from card)
Ship the server side of F7 "Ask Paw Care Right +": `ChatThread`/`ChatMessage` models,
`POST /v1/chat/threads`, and `POST /v1/chat/threads/:id/messages` streaming the answer over
SSE — with pet context + a last-90d timeline digest injected, the **same** safety policy
module the triage prompt uses, a deterministic structured-check **nudge** for symptom-like
messages, and premium gating + a fair-use quota of 200 messages/month. No mobile work (T083).

## Safety statement (PRODUCT_SPEC §5 / CLAUDE.md §7 — LOAD-BEARING, non-negotiable)
1. **One policy module, no fork.** The ABSOLUTE SAFETY RULES block currently inlined in
   `packages/ai/src/triage/system-prompt.ts` is *moved verbatim* into a new shared
   `packages/ai/src/safety/policy.ts` and imported by BOTH the triage prompt and the chat
   prompt. The triage prompt's rendered output must remain **byte-identical** (its existing
   snapshot/spec must pass untouched) — that is the proof there is no fork and no drift.
2. **Fail upward, never silently guess.** Every failure mode of the message endpoint —
   provider error, provider timeout, stream abort, empty completion, or any detector finding
   in the generated text — terminates the stream with the **safe fallback message** and
   `done.status = "SAFE_FALLBACK"`. There is no silent retry, no partial unsafe text left on
   screen, and no bare `error` event that would leave the user with nothing.
3. **Output gate before release.** Text is released to the client only after the T038 detector
   (`scanUnsafeText`, the same pattern set as `scanUnsafe`) has scanned it. Any finding ⇒ stop
   consuming the provider stream, discard un-released buffer, emit the fallback, persist the
   assistant message as `SAFE_FALLBACK`. (Span-level replacement + incident logging + chat
   red-team eval cases are **T082**, not this task — see Out of scope.)
4. **No diagnosis / no dosing.** The chat system prompt carries the shared policy verbatim and
   adds chat-specific framing only. The 90-day digest is a **records-only** rendering (dates +
   recorded facts, no interpretation) and, by decision D6, carries **no medication names or
   doses at all** — only a count. No new user-facing copy in this task claims diagnosis, names
   a drug, or contains a dose.
5. **Symptom-like input is steered to the structured flow BEFORE any AI text.** The nudge is a
   deterministic keyword detector (code, not a model); when it fires, the `nudge` event is
   emitted immediately after `start` and always **before** the first `chunk`.
6. **Quota never gates a safety surface.** The chat quota is chat-only. It is consumed inside
   the chat message handler and nowhere else; no check/emergency/red-flag/interstitial code
   path is touched. An explicit e2e re-asserts that after chat quota exhaustion a red-flag
   symptom check still returns 201 with its `redFlag` payload.
7. **Untrusted input is data, never instructions.** The owner's message is sanitized
   (control/zero-width chars stripped, role-marker lines defanged, length-capped) and wrapped
   in an explicit delimited block that the system prompt declares to be untrusted data.
8. No SAFETY-ESCALATION: the card is implementable without weakening any safety surface.

## Key decisions (each is a design choice — scrutinize; risks restated at the end)
- **D1 — Stream from the request handler, NOT a BullMQ worker.** CLAUDE §6 sends "long-running
  work (AI calls…)" to workers, but that rule exists to keep *request handlers from blocking on
  work whose result the caller is not waiting for*. Here the HTTP response **is** the work: an
  SSE response must hold the socket open for its whole life, so a worker+Redis-pubsub relay
  would still pin the same request handler, add a hop, add a new pubsub channel + lifecycle,
  and *increase* time-to-first-token — pure cost, zero benefit. Repo precedent agrees: there is
  no SSE/pubsub relay anywhere in `apps/api` today. Bounded by a hard provider timeout
  (`CHAT_STREAM_TIMEOUT_MS = 60_000`) and the per-message quota. Non-interactive AI work
  (triage) stays on BullMQ, unchanged.
- **D2 — Raw `@Res()` Express SSE writer, NOT Nest's `@Sse()`.** `@Sse()` is itself a **GET**
  route decorator; ARCHITECTURE §API pins `POST /chat/threads/:id/messages` (SSE stream) and the
  request carries a body. So the controller takes `@Res() res: Response` and writes frames
  through a small tested `SseWriter` helper. Consequence (§5-critical, enforced by step order):
  every rejection — 404 pet/thread, 400 validation, 402 gate/quota — happens **before** any SSE
  header is written, so `AllExceptionsFilter` still produces the standard
  `{error:{code,message,requestId}}` JSON envelope for those.
- **D3 — `TextProvider` gains an OPTIONAL `generateStream`.** Additive optional method; every
  existing provider (`ollama-vision`, `gemini-image`, both fakes) stays valid unchanged.
  Implemented for real by `OllamaTextProvider` (OpenAI-compatible `stream:true` + `data:` line
  parsing) and by `FakeTextProvider` (scripted chunks). `ChatService` uses `generateStream`
  when the injected provider implements it, and otherwise degrades to `generate()` + a single
  chunk — so a provider without streaming still yields a correct, safe answer.
- **D4 — Digest builder is a PURE function in `packages/ai`, mirroring `buildVetSummary`'s
  shape but not reusing it.** `buildVetSummary` lives in `apps/api`, is user-facing, and ends
  with a user-facing disclaimer + char budget aimed at a vet handoff; `packages/ai` must not
  import `apps/api`. So `buildTimelineDigest` is a new pure, clock-free, model-facing builder
  over already-90d-windowed rows. The 90-day window (`Date.now()`) is read exactly once, in
  `ChatService`, exactly like `HealthLogsService.vetSummary` does.
- **D5 — Nudge fires on the *user's* message only, deterministically, pre-stream**, and maps to
  an existing `SymptomCategory` from `@pawcareright/types` (`SYMPTOM_CATEGORIES`). The API sends
  only `{category}`; user-facing nudge copy belongs to mobile (T083, CLAUDE §6 "no hardcoded
  user-facing strings").
- **D6 — The chat digest contains NO medication names or doses**, only
  `Medication doses recorded (last 90 days): N`. Deliberately narrower than the vet summary
  (whose audience is a vet): keeping drug names out of the chat context removes the single
  largest §7 rule-2 leakage surface for a free-form text answer.
- **D7 — Chat gating is two-stage, mirroring T075**: (a) feature lock — `tier === "FREE"` ⇒
  402 `PAYMENT_REQUIRED`; then (b) `QuotaService.consume(userId, "chatMessages", entitlement)`
  ⇒ 402 when exceeded. `FREE.chatMessages = { window:"month", limit: 0 }` is belt-and-braces
  behind the explicit feature lock. No new `ErrorCode` (T075 decision 1 stands).
- **D8 — Exactly four SSE event types, in a fixed total order:** `start` → (`nudge`)? →
  `chunk`* → `done`. `chunk.seq` starts at 0 and increases by exactly 1. `done` is emitted
  exactly once and is always last. There is **no** `error` event (see Safety statement 2).

## SSE contract (pin exactly — the AC test asserts this)
Response headers: `Content-Type: text/event-stream; charset=utf-8`,
`Cache-Control: no-cache, no-transform`, `Connection: keep-alive`, `X-Accel-Buffering: no`,
plus quota headers (ARCHITECTURE §API "quota headers"): `X-Quota-Limit`, `X-Quota-Remaining`.

```
event: start
data: {"threadId":"…","userMessageId":"…","assistantMessageId":"…"}

event: nudge                       // 0 or 1 times, only immediately after start
data: {"category":"vomiting"}

event: chunk                       // 0..n times, seq 0,1,2,…
data: {"seq":0,"text":"…"}

event: done                        // exactly once, always last
data: {"assistantMessageId":"…","status":"OK","quota":{"used":3,"limit":200,"remaining":197}}
```
Frame format is exactly `event: <name>\ndata: <json>\n\n`. `status` ∈ `"OK" | "SAFE_FALLBACK"`.

## Endpoint specs — ORDER IS §5-CRITICAL

**`POST /v1/chat/threads`** body `{petId}` → 201 `{id, petId, createdAt}`
1. `petsService.findOne(householdId, petId)` → 404 if absent (never leaks).
2. `entitlementResolver.resolve(userId, householdId)`; `tier === "FREE"` ⇒
   `new HttpException("Ask Paw Care Right + is a premium feature.", HttpStatus.PAYMENT_REQUIRED)`.
3. Create `ChatThread`. No quota consumed (threads are free to open for premium users; only
   messages are metered).

**`POST /v1/chat/threads/:id/messages`** body `{content}` → `text/event-stream`
1. Load the thread scoped to the caller's household
   (`prisma.chatThread.findFirst({where:{id, pet:{householdId, deletedAt:null}}, include:{pet:true}})`)
   → 404 if absent. **JSON error, no SSE headers yet.**
2. Validation is the global `ValidationPipe` (400). **JSON error, no SSE headers yet.**
3. Entitlement: FREE ⇒ 402 (feature lock). **JSON, no SSE headers yet.**
4. `quotaService.consume(userId, "chatMessages", entitlement)`; `!allowed` ⇒ 402
   ("Monthly chat fair-use limit reached."). **JSON, no SSE headers yet.**
5. Persist the USER `ChatMessage` (raw content as typed, capped by the DTO).
6. `detectSymptomNudge(content)` (deterministic, pre-AI).
7. Build the prompt: pet context + `buildTimelineDigest(...)` (90-day window computed here,
   the only `Date.now()` read) + last `CHAT_HISTORY_TURNS` turns + sanitized owner message.
8. `sse.writeHead(...)` with the quota headers; emit `start` (with a pre-generated
   `assistantMessageId` via `randomUUID()`); emit `nudge` if step 6 fired.
9. Stream: accumulate provider deltas into `pending`; when `pending` ends at a boundary
   (`\n`, `. `, `! `, `? `) **or** exceeds `CHAT_RELEASE_BOUNDARY_CHARS`, scan the releasable
   prefix with `scanUnsafeText`; clean ⇒ emit `chunk` with the next `seq`; any finding ⇒ stop
   consuming the stream, discard `pending`, emit the fallback `chunk`, mark
   `status = SAFE_FALLBACK`. At end of stream, scan and release the tail the same way.
10. Failure modes ⇒ same fallback path: provider throws / times out / stream ends with zero
    released text. **Never** re-prompt, never partially deliver flagged text.
11. Persist the ASSISTANT `ChatMessage` (`id` = the pre-generated one, `content` = exactly what
    was delivered, `status`, `nudgeCategory`, `promptVersion`, `modelId`, `costMicroUsd`);
    log cost via `CostLogService`; emit `done`; `sse.end()`.
12. If the client disconnects (`res.on("close")`), abort the provider stream and still persist
    what was delivered. Never throw out of the handler after headers are sent.

## Risks & the decisions the planner made (for the checker)
- **R1 (D1) — streaming in the request handler vs CLAUDE §6's "AI calls go through BullMQ".**
  This is a deliberate, argued exception, limited to the interactive SSE endpoint: the caller
  waits on this exact response, so a worker+pubsub relay pins the same socket while adding a
  hop and latency. Mitigations: hard `CHAT_STREAM_TIMEOUT_MS`, per-message quota, abort on
  client disconnect. Triage/vision/push work stays on BullMQ. If the checker rejects this, the
  alternative (worker + Redis pubsub relay) is a strictly larger change, not a smaller one.
- **R2 (D3) — extending the T029 provider seam.** `generateStream` is optional and additive, so
  no existing implementation or caller changes; the chat service degrades gracefully when it is
  absent. Risk is the new hand-rolled SSE parser in `ollama-text.ts` (split deltas, `[DONE]`,
  malformed lines) — covered by `ollama-stream.spec.ts` with a mocked `fetch`/ReadableStream.
  This code is never on the triage path.
- **R3 (Safety 1) — moving `SAFETY_RULES_SECTION` out of `triage/system-prompt.ts`.** A single
  stray character changes the triage prompt and therefore triage behaviour. The guard is
  mechanical: existing triage specs must pass **unmodified**; the executor is forbidden from
  editing them to accommodate a drift.
- **R4 (D7/Safety 3) — T081 aborts the whole answer on a detector finding, where T082 will do
  span-level replacement.** Coarser than the final design, but strictly safer (delivers less),
  and it means the endpoint is never shipped without an output gate. Slight over-blocking is
  possible (e.g. an owner asking about a drug, where a compliant warning-context mention could
  still trip a `DOSING` number pattern) — that fails upward to the vet-referral fallback, which
  is the correct direction.
- **R5 (D6) — no medication names in the chat digest.** Costs some context ("he's on his
  arthritis meds") in exchange for removing the biggest §7 rule-2 leakage surface. If T082 or a
  later card wants med context, it must add it with its own detector coverage.
- **R6 (D5) — a keyword nudge detector has false negatives.** Unusual phrasing may not nudge;
  the shared safety prompt still instructs the model to redirect symptom talk and to escalate
  life-threatening signs. False positives are cheap (an extra tappable card). The detector is
  deliberately deterministic code, never a model call.
- **R7 (D4) — digest query duplication.** `ChatService` re-issues 90-day queries that resemble
  `HealthLogsService.vetSummary`'s. Accepted rather than widening `HealthLogsService`'s public
  API for a different consumer with a different (records-only, no-med-names) projection; the
  shapes genuinely differ.
- **R8 — supertest and SSE.** Supertest buffers the whole response, so the e2e reads `res.text`
  and parses frames from it. That verifies *order and content*, not wall-clock incrementality.
  Accepted: chunk **order** and the single terminal `done` event are exactly what the AC asks
  for, and the `SseWriter` unit spec covers frame formatting.
- **R9 — `@Res()` bypasses Nest's response pipeline.** Any exception thrown *after* headers are
  sent cannot produce the JSON error envelope, which is why steps 1–4 (404/400/402) all run
  before `writeHead`, and why post-header failures are funnelled into the fallback + `done`
  rather than thrown. The controller must not `return` a value on the SSE route.
- **R10 — quota TOCTOU / partial consumption.** The Redis `INCR` is consumed before the provider
  call, so a message that ends in `SAFE_FALLBACK` still counts against the 200/mo fair-use cap.
  Accepted (matches the checks path, avoids a refund path that could be abused); the cap is a
  fair-use ceiling, not a billing meter.
- **R11 — `FREE.chatMessages.limit = 0` is redundant** with the explicit FREE feature lock. Kept
  deliberately as defence in depth so a future caller that forgets the tier gate still cannot
  consume chat.
