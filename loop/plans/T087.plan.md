# T087 · In-app content reader — execution plan

**Card (docs/PHASES.md):** *Deps: T084 · Do:* Breed guide screen from pet profile ("About {breed}") +
explore list; markdown-ish renderer for dataset content blocks. *Accept:* Renders exemplar guides;
deep link works; a11y labels on sections.

**Size:** S. **Workspace touched:** `apps/mobile` only (plus loop bookkeeping).

## Safety statement (read before writing any code)

1. **This is NOT an AI surface and NOT a §5 policy change.** Every word rendered by this task comes
   from either (a) the static, human-reviewed `packages/data` breed-guide dataset (T084, already
   detector-linted for dosage/diagnosis language) or (b) new navigation/section-label copy in
   `apps/mobile/src/strings.ts`. No prompt, no provider call, no triage output, no urgency tier.
2. **Nothing weakens a Safety Policy surface.** `<VetDisclaimer/>`, the Emergency interstitial,
   region hotlines, the red-flag rules engine, the output gate and the fail-upward fallbacks are
   **imported/untouched**. This task *adds* a disclaimer render site; it removes none. `apps/api`,
   `packages/ai`, `packages/data`, `packages/types` are not modified at all.
3. **Condition-awareness items render verbatim.** `commonConditionAwareness[].prompt` is printed
   exactly as it appears in the dataset — never truncated, never reworded, never merged with the
   `topic`, never turned into an assertion about the reader's pet. The T084 schema guarantees each
   starts with `VET_PROMPT_PREFIX = "Talk to your vet about "`; a test re-asserts that at render time.
4. **Drafts can never reach a screen.** Only `publishedBreedGuides` / `getBreedGuide` from
   `@pawcareright/data` may be imported by app code. `allBreedGuides` is FORBIDDEN in
   `apps/mobile/**` — this is the explicit T084 hand-off (`loop/reviews/T084.review.md` F3,
   `loop/plans/T084.plan.md` R3) and is enforced by a source-scan test in this task (step 9).
5. **New copy contains no diagnosis, dosing, drug-name, cure/prevent/treat, or streak language.** A
   tone scan over `strings.breedGuide` enforces it (mirrors `chat-strings-tone.test.ts`).
6. Not a SAFETY-ESCALATION card. No blocked file needed.

## Decisions (deliberate, minimal — scrutinise these)

- **D1 — "markdown-ish renderer" = a typed structured-section renderer, NOT a markdown engine.**
  T084's D6 fixed the content model as four typed fields (`temperament`, `exerciseNeeds{level,
  narrative}`, `commonConditionAwareness[]`, `groomingCadence{frequency,narrative}`) with **no
  free-form markdown body anywhere in the dataset**. There is no `#`/`**`/list syntax to parse.
  Adding a markdown parser (new dependency, CLAUDE §2 rule 7) to render zero markdown would be
  over-engineering (CLAUDE §2 rule 2). The renderer therefore maps each typed block to a titled
  section. **No new dependency in this task.**
- **D2 — Route shape `app/breeds/[species]/[slug].tsx`, species lowercased in the URL.**
  T084 D2 pins guide identity as the pair `(species, slug)` (slugs are unique only within a
  species). A single-segment `[slug]` route could resolve the wrong species' guide. Deep link:
  `pawcareright://breeds/dog/labrador-retriever`. The screen uppercases + validates the species
  param against the `BREED_SPECIES` union; anything else redirects to `/breeds`.
- **D3 — The detail screen renders `<VetDisclaimer/>`; the explore list does not.**
  CLAUDE §7 rule 3 mandates it on *AI result* screens, which this is not — but the T084 review
  recorded "T087 … must render `<VetDisclaimer/>`" as an explicit acceptance item, and the detail
  screen prints health-adjacent (vet-conversation) content. Failing upward, it renders. The explore
  list shows only breed names + a neutral subtitle — no health content — so it carries the short
  `strings.breedGuide.listNote` provenance/intent line instead (rendering the full disclaimer on a
  pure index screen dilutes it; precedent: `services/index.tsx`, `care-plan/[petId].tsx` both
  document *why* they do not render it).
- **D4 — `src/components/vet-disclaimer.tsx` is NOT modified.** It ships light-only classes
  (`bg-brand-50`/`text-brand-900`, no `dark:` variants). Fixing that is a §5-component change that
  would ripple into `check-result-snapshot` / `chat-screen-snapshot` and is out of this card's
  scope. The new screen's own dual-theme test scopes its `dark:` assertions to the screen's own
  containers. Logged as R4.
- **D5 — Two entry points, both minimal:** (a) contextual "About {breed}" row on the pet profile,
  rendered **only** when `getBreedGuide(pet.species, pet.breedSlug)` returns a guide; (b) a global
  "Breed guides" row in Settings (byte-pattern copy of the existing `settings-services` `ListRow`),
  so the explore list is reachable for owners whose pet has no published guide. Without (b) the
  explore list would be unreachable dead code for 45 of 50 breeds.
- **D6 — Screen states.** Data is a frozen local array parsed at module load: **no loading, no
  error, no offline state applies** (precedent + wording: `services/index.tsx` "Static local data
  throughout — no query, so the §6 four-data-states rule does not apply here"). Two guarded states
  do exist and are tested: explore list **empty** (impossible with today's 5 exemplars, so tested
  via a mocked-empty content module) and detail **not-found / not-yet-published** (reachable today:
  any of the 45 draft slugs).
- **D7 — Display names come from the breeds dataset (`allBreeds`).** `BreedGuide` has no `name`
  field. Same precedent as `src/weight/breed-weight-band.ts` (imports `@pawcareright/data`, matches
  on `slug` + `species`). Guides whose slug has no breed row are skipped, and a parity test pins
  `listPublishedBreedGuides().length === publishedBreedGuides.length` so silent loss is impossible.
- **D8 — Enum labels live in `strings.ts`** as `Record<ExerciseLevel,string>` /
  `Record<GroomingFrequency,string>`; the content module returns the raw enum values (no copy in
  `src/content/**`, CLAUDE §6 "strings externalized").
- **D9 — No `app/breeds/_layout.tsx`.** `app/services/*` and `app/checks/*` have none; the root
  stack handles these routes. Do not add one.

## Ordered steps

1. **Verify the data contract (read-only).** Confirm `@pawcareright/data` exports
   `publishedBreedGuides`, `getBreedGuide(species, slug)`, `allBreeds`, types `BreedGuide`,
   `ExerciseLevel`, `GroomingFrequency`, `BreedSpecies`, and the constant `VET_PROMPT_PREFIX`.
   Confirm the 5 published exemplars are exactly: DOG `labrador-retriever`, `golden-retriever`,
   `german-shepherd`; CAT `maine-coon`, `persian`. Confirm at least one *draft* slug for the
   negative tests (DOG `beagle`). If any name differs, stop and use the real name — do not invent.
2. **Verify the mobile anchors (read-only).** `Pet` from `@pawcareright/types` has
   `species: "DOG"|"CAT"` and `breedSlug: string | null`. `ScreenScaffold` accepts
   `title/subtitle/onBack/scrollTestID`. `useNavBack(fallback)` exists in
   `src/hooks/use-nav-back.ts`. `ListRow`, `Card`, `SectionHeader`, `EmptyState`, `VetDisclaimer`,
   `AppHeader` exist under `src/components/`. `apps/mobile/package.json` already depends on
   `@pawcareright/data` (it does — no manifest edit).
3. **`apps/mobile/src/strings.ts` (modify).** Add ONE new top-level namespace `breedGuide` (place it
   after the existing `services` namespace; do not reorder or edit any existing key):
   - `title: (breedName: string) => \`About ${breedName}\`` — the pet-profile row label AND the
     detail screen title.
   - `listTitle`, `listSubtitle`, `listNote` (honest: these guides are general breed information
     reviewed by our content team, not advice about your pet).
   - `sections: { temperament, exercise, conditions, grooming }` (section headings).
   - `conditionsIntro` — one neutral line framing the items as questions to raise with a vet.
   - `exerciseLevel: Record<ExerciseLevel, string>` and `groomingFrequency:
     Record<GroomingFrequency, string>` label maps (typed with the imported unions).
   - `provenance: (reviewedBy: string, reviewedAt: string) => string` — honest provenance line
     built from dataset values only (e.g. "Reviewed by {reviewedBy} on {reviewedAt}").
   - `notFoundTitle`, `notFoundBody`, `notFoundCta` (detail screen, unknown/unpublished guide).
   - `emptyTitle`, `emptyBody` (explore list with zero published guides).
   - `speciesGroup: { DOG, CAT }` — group headings on the explore list.
   - a11y: `sectionA11y: (sectionTitle: string) => string`, `rowA11y: (breedName: string) => string`.
   **Copy constraints (tested in step 9):** no `diagnos*`, no drug name/`mg`/`dose`/`administer`,
   no `cure|treat|prevent|healthy|healthier|better`, no streak/pressure framing, no currency, no
   year literal. Do **not** hardcode `Paw Care Right +` — if the product name is needed, take
   `APP_DISPLAY_NAME` from `@pawcareright/config` at the call site (CLAUDE §1a).
4. **`apps/mobile/src/content/breed-guide-content.ts` (create).** Pure module, no React. Imports
   ONLY `publishedBreedGuides`, `getBreedGuide`, `allBreeds` and types from `@pawcareright/data`
   (never `allBreedGuides`).
   - `export interface BreedGuideEntry { guide: BreedGuide; breedName: string }`
   - `export function resolveBreedGuideForPet(species: BreedSpecies, breedSlug: string | null):
     BreedGuideEntry | null` — returns `null` for `null`/empty slug, for an unpublished draft, for
     an unknown slug, and when no breed row supplies a name.
   - `export function resolveBreedGuideEntry(species: BreedSpecies, slug: string): BreedGuideEntry
     | null` — same lookup for the route params (the pet-facing helper delegates to it).
   - `export function listPublishedBreedGuides(): BreedGuideEntry[]` — every published guide with a
     name, sorted **DOG group first, then CAT**, each group A→Z by `breedName` (`localeCompare`).
   - `export function parseSpeciesParam(raw: string | undefined): BreedSpecies | null` —
     `"dog"`/`"DOG"` → `"DOG"`, `"cat"`/`"CAT"` → `"CAT"`, everything else → `null`.
   - `export function guideRouteParams(entry: BreedGuideEntry): { species: string; slug: string }` —
     `{ species: entry.guide.species.toLowerCase(), slug: entry.guide.slug }` (one place builds the
     deep-link params, so the screen and the pet row cannot drift).
   No `any`, no `@ts-ignore`, no `console.log`.
5. **`apps/mobile/src/components/breed-guide-sections.tsx` (create).** The "markdown-ish" renderer
   (D1). Props `{ guide: BreedGuide }`. Presentational only — no navigation, no data access.
   Renders, in order, inside `<View testID="breed-guide-sections">`:
   1. `temperament` section — `testID="breed-guide-section-temperament"`.
   2. `exercise` section — `testID="breed-guide-section-exercise"`, a level chip
      (`testID="breed-guide-exercise-level"`, text from `strings.breedGuide.exerciseLevel[level]`)
      + `narrative` verbatim.
   3. **condition-awareness section** — `testID="breed-guide-section-conditions"`,
      `strings.breedGuide.conditionsIntro`, then one row per item
      (`testID={\`breed-guide-condition-${index}\`}`) showing `topic` as a label and `prompt`
      **verbatim, unmodified, untruncated** (`numberOfLines` must NOT be set).
   4. `grooming` section — `testID="breed-guide-section-grooming"`, frequency chip
      (`testID="breed-guide-grooming-frequency"`) + `narrative` verbatim.
   5. provenance line — `testID="breed-guide-provenance"`, rendered **only** when both
      `provenance.reviewedBy` and `provenance.reviewedAt` are present, using those exact dataset
      values via `strings.breedGuide.provenance(...)`. Never claim a review that the data does not
      record; never render `generatedBy`/`model` as a human reviewer.
   **A11y (AC3):** every section title `<Text accessibilityRole="header" maxFontSizeMultiplier={1.5}>`;
   every section container `accessibilityLabel={strings.breedGuide.sectionA11y(sectionTitle)}`.
   **Theme:** NativeWind classes with `dark:` pairs on every surface/text (design-system §1.1a
   tokens already used elsewhere: `bg-surface-card`/`dark:bg-surface-card-dark`,
   `text-brand-900`/`dark:text-ink-dark`, `text-brand-700`/`dark:text-ink-muted-dark`,
   `border-brand-100`/`dark:border-hairline-dark`). No inline style objects.
6. **`apps/mobile/app/breeds/[species]/[slug].tsx` (create).** Detail screen + deep-link target.

## Risks (each is a design decision the checker should scrutinise)

- **R1 (D1) — "markdown-ish renderer" is interpreted as a structured-section renderer.** If the
  checker reads the card as requiring a real markdown parser, this plan under-delivers. Argument:
  T084 D6 explicitly says "no free-form markdown body … T087's 'markdown-ish renderer for dataset
  content blocks' renders these four fields as sections", the dataset contains zero markdown syntax,
  and a parser would be a new dependency (CLAUDE §2 rule 7) rendering nothing.
- **R2 (D3) — the disclaimer decision is a judgement call.** CLAUDE §7 rule 3 scopes the mandate to
  AI result screens; this is static reviewed content. Rendering it is the fail-upward choice and
  matches the recorded T084 hand-off, but a reviewer could argue either (a) it is unnecessary here,
  or (b) it should also appear on the explore list. Stated so it can be overruled cheaply — the
  component is one JSX line in each screen.
- **R3 (D5) — the Settings entry point is arguably scope creep.** The card names only the pet
  profile entry and the explore list. Without a global entry, the explore list is unreachable for a
  pet whose breed has no published guide (45 of 50 breeds). One `ListRow` is the smallest possible
  wiring; if the checker rejects it, delete that row and the two lines in `strings.ts` — nothing
  else depends on it.
- **R4 (D4) — `<VetDisclaimer/>` has no dark-theme classes.** On the new screen in dark mode it will
  render a light cream block. Fixing it means editing a §5 component and rebaselining
  `check-result-snapshot` / `chat-screen-snapshot`, which is out of scope for an S card. Recorded
  here as a known cosmetic defect and a candidate T088 sweep item, not silently ignored.
- **R5 (AC2) — "deep link works" is proven in-repo, not on device.** RNTL cannot exercise native
  `getInitialURL` scheme→route mapping. Identical deferral to T050 (`check-deeplink-route.test.tsx`
  header comment). Mitigation: correct route file path, canonical params built in one helper
  (`guideRouteParams`), cold-start-from-params-only test, and redirect coverage for bad params.
  On-device verification belongs to the M8 gate / T088.
- **R6 (D6) — the explore-list empty state can never trigger with today's data.** It is tested only
  through a mocked content module. Justification: CLAUDE §6 requires the state to exist; the mock
  proves the code path is live rather than dead. The loading/error/offline states are deliberately
  **absent** (local synchronous data) and this must be documented in each screen's doc comment so a
  reviewer sees a decision, not an omission.
- **R7 (D7) — display names come from a second dataset (`allBreeds`).** If a guide slug ever loses
  its breed row, that guide silently disappears from the explore list. Mitigation: the parity test
  in AC1 fails the build the moment the two datasets diverge (T105 also audits this).
- **R8 — `apps/mobile/src/strings.ts` is a large shared file.** The edit must be purely additive;
  reordering or touching existing keys risks breaking the four existing tone-scan suites and several
  screen tests. Verify with `git diff` that only added lines appear.
- **R9 — pet-profile regression surface.** `apps/mobile/app/pets/[id].tsx` is covered by
  `pet-home-screen.test.tsx` and `pet-home-snapshot.test.tsx`. The new row sits inside
  `pet-home-scroll` (below quick actions), so the above-the-fold CTA budget is unaffected — but the
  pet-home snapshot **will** need rebaselining for a pet whose fixture has a published-guide breed.
  Inspect that snapshot diff line by line; if the fixture pet has no published breed guide, the
  snapshot must be **unchanged** — an unexpected diff means the conditional guard is wrong.
