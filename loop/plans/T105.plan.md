# Plan — T105: Seed & dataset QA

## Objective (from card)
Final dataset audit: counts, spot-check of the top-100 toxin verdicts against the sources list, a region
hotline verification table with a verified-by-human column for C3, and a reviewed-flag inventory for breed
guides. **Accept:** audit report `docs/qa/dataset-audit.md`; all schema meta-tests green.

Deliverable design: the report is **generated from the real datasets** by a pure renderer + a CLI (house
idiom), and a pinned doc-spec asserts the committed markdown is byte-identical to the renderer output — so
no count, tally, or table row in the doc can drift from `packages/data`.

## Risks & the decisions the planner made (scrutinize these)

1. **D1 — "Top-100" is defined by verdict severity, not popularity.** No commonness/popularity/severity field exists on `ToxinRow` (finding 1), so the only in-data ordering signal is `FOOD_VERDICT_SEVERITY` (finding 2). Order: max(dog,cat) severity desc → min desc → category index asc → id asc; take 100. *Risk:* "top-100" could be read as "most-searched items", which this is not. *Mitigation:* §4.1 states the definition, why no popularity signal exists, and that the ordering biases the window toward `emergency`/`toxic` rows — the correct bias for safety QA. T3 pins determinism.
2. **D2 — Source attribution is category-level, and the doc says so.** Because T035 R9 stored sources as file-header comments with no per-row field, "spot-check verdicts against sources list" is mechanised as *"every spot-checked row's category resolves to ≥1 declared source that provably appears verbatim in that category's data-file header"* (T1/T4), **not** as per-verdict citation. *Risk:* a reader could over-read this as per-verdict sourcing. *Mitigation:* §3 and §8 state it explicitly; §4.3's per-row human column stays `UNVERIFIED`.
3. **D3 — The doc is byte-generated and pinned by equality (T9).** Strongest possible anti-drift, but any renderer change requires re-running the CLI, and a stray timestamp would make the spec fail on the next machine. *Mitigation:* the "no `Date`, no cwd, no version" rule in step 5, plus T8. *Risk accepted:* hand-editing the doc fails the suite — which is the point.
