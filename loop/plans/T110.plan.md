## 2. Design

### 2.1 The one architectural idea: resolve at module scope, identity fast-path for English

`strings` stays exactly what it is today — a module-scope constant with the same shape and the
same literal types. The i18n layer sits *underneath* it:

```
enStrings  (the existing literal tree, renamed in place)
     |
     v
resolveActiveStrings(enStrings)   -> if activeLocale === "en": returns enStrings BY IDENTITY
     |                                else: deep-merges the locale override onto English
     v
export const strings              -> type is `typeof enStrings` (literal types preserved)
```

Consequences (all of them are the point):

* **All 183 call sites are untouched.** No provider, no hook, no prop drilling.
* **English is byte-identical and reference-identical** (`strings === enStrings`), so the 19
  snapshots (F5), both detector lints (F3), and every frozen-copy pin (F3/F4) keep passing
  *without being modified at all*.
* Types are preserved exactly: `resolveActiveStrings<T>(en: T): T`.
* Locale changes require an app reload — which is the **honest** RN semantic anyway, since
  `I18nManager.forceRTL` requires a reload. Documented, not hidden.

### 2.2 Locale registry (shared, `packages/config/src/i18n/locales.ts`)

```ts
export type LocaleId = "en" | "es" | "pt-BR" | "hi" | "ar" | "en-XA" | "ar-XB";

export interface LocaleEntry {
  readonly id: LocaleId;
  readonly englishName: string;
  readonly direction: "ltr" | "rtl";
  /** TRUE only after a human reviewer (and, for safety copy, a veterinarian) has signed off. */
  readonly reviewed: boolean;
  /** Dev/CI-only pseudolocale — never selectable from device detection, never served. */
  readonly pseudo: boolean;
  readonly source: "authored" | "machine" | "generated";
}

export const DEFAULT_LOCALE: LocaleId = "en";
export const LOCALES: Readonly<Record<LocaleId, LocaleEntry>>;
export const RTL_LANGUAGES: readonly string[]; // ["ar","he","fa","ur"]

export function getTextDirection(locale: string): "ltr" | "rtl";   // base-language lookup: "ar-XB" -> rtl
export function isRtlLocale(locale: string): boolean;
export function isSupportedLocale(value: string): value is LocaleId;

/** Accept-Language / device-locale-list negotiation. Pure. Exact -> base-language -> DEFAULT. */
export function negotiateLocale(candidates: readonly string[]): LocaleId;
export function parseAcceptLanguage(header: string | null | undefined): string[]; // q-sorted tags

/**
 * THE SAFETY GATE. Maps any locale to the locale actually served.
 * Returns DEFAULT_LOCALE unless LOCALES[locale].reviewed === true.
 */
export function resolveServedLocale(locale: string): LocaleId;

/**
 * Full selection: dev override (ignored when NODE_ENV === "production") wins;
 * otherwise negotiate the device/header candidates, then pass through resolveServedLocale.
 */
export function selectActiveLocale(args: {
  override?: string | null;
  candidates?: readonly string[];
  nodeEnv?: string;
}): LocaleId;
```

Registry contents shipped by T110 — **every non-`en` entry is `reviewed: false`**:

| id | direction | reviewed | pseudo | source |
|---|---|---|---|---|
| `en` | ltr | **true** | false | authored |
| `es` | ltr | false | false | machine |
| `pt-BR` | ltr | false | false | machine |
| `hi` | ltr | false | false | machine |
| `ar` | **rtl** | false | false | machine |
| `en-XA` | ltr | false | **true** | generated |
| `ar-XB` | **rtl** | false | **true** | generated |

`en-XA` / `ar-XB` are the **Android-standard pseudolocale identifiers** (accented-expansion and
RTL-bidi respectively). `ar` is registered for direction/negotiation only and ships **no
dictionary** in T110 (see D4).

### 2.3 Resolver + shape pinning (`packages/config/src/i18n/resolve.ts`)

```ts
/** Structural pin: an override may omit keys, but may never add one or change a leaf's kind. */
export type LocaleOverrides<T> = {
  readonly [K in keyof T]?: T[K] extends string
    ? string
    : T[K] extends (...args: infer A) => string
      ? (...args: A) => string
      : T[K] extends readonly (infer U)[]
        ? readonly U[]
        : LocaleOverrides<T[K]>;
};

/** Deep merge. Returns `en` BY IDENTITY when `overrides` is undefined/empty. Never mutates. */
export function resolveStrings<T>(en: T, overrides?: LocaleOverrides<T>): T;

/** Every dotted leaf path of a tree (strings, fns, array items, nested objects). */
export function collectLeafPaths(tree: unknown): string[];
/** Leaf paths actually provided by an override tree. */
export function collectOverridePaths(overrides: unknown): string[];
```

Merge rules: plain object → recurse; **everything else (string / function / array) → replace
wholesale**. `undefined` override value → keep English. Arrays are never merged element-wise.

Extra keys are a **compile error** (excess-property check via `satisfies LocaleOverrides<...>` at
each dictionary's definition site). Missing keys are legal by design (English fallback) and are
governed by the section-coverage test (§2.5).

### 2.4 Pseudolocales (`packages/config/src/i18n/pseudo.ts`)

```ts
export const PSEUDO_OPEN = "⟦";   // ⟦
export const PSEUDO_CLOSE = "⟧";  // ⟧
export const RTL_MARK = "‏";      // RLM

/** "Home" -> "⟦Ĥöṁé⟧" — accented + bracketed, length-expanded ~30%. */
export function pseudoString(value: string): string;
/** "Home" -> RLM + "⟦Ĥöṁé⟧" + RLM. */
export function rtlPseudoString(value: string): string;
/** Walks a whole tree; string leaves transformed, function leaves WRAPPED so their RESULT is transformed. */
export function pseudoTree<T>(tree: T, transform: (s: string) => string): T;
/** True iff the value carries the pseudo markers. */
export function isPseudoTransformed(value: string): boolean;
```

`pseudoTree` is what makes the leak test possible: after it runs, **every** byte of copy that
came from the strings tree is visibly marked, so anything unmarked on screen is a hardcoded
literal. Pseudolocale dictionaries are *generated at runtime from the English tree*, never
authored — so they cost 0 maintenance and can never drift.

### 2.5 Per-app runtime + dictionaries (mobile shown; web is the same shape)

`apps/mobile/src/i18n/runtime.ts`
```ts
export function detectDeviceLocales(): string[];      // expo-localization, try/catch -> [] on ANY failure
export function getActiveLocale(): LocaleId;          // memoized, computed once at module init
export function getActiveDirection(): "ltr" | "rtl";
export function resolveActiveStrings<T>(en: T): T;    // registry lookup -> resolveStrings
```
`detectDeviceLocales()` is reached at module-init time (via `strings.ts`) and **must be wrapped in
try/catch returning `[]`** — a throw here would break every screen in the app. Override source:
`process.env.EXPO_PUBLIC_I18N_LOCALE` (web: `process.env.NEXT_PUBLIC_I18N_LOCALE`), honored only
when `process.env.NODE_ENV !== "production"`.

`apps/mobile/src/i18n/locale-registry.ts`
```ts
import type { StringsShape } from "../strings";   // TYPE-ONLY: erased, so there is NO runtime cycle
export const TRANSLATED_SECTIONS: Readonly<Record<"es" | "pt-BR" | "hi", readonly string[]>>;
export const SAFETY_PINNED_PREFIXES: readonly string[];
export function getLocaleOverrides(locale: LocaleId): LocaleOverrides<StringsShape> | undefined;
```

**`TRANSLATED_SECTIONS` (identical for all three machine locales) — mobile:**
`tabs`, `nav`, `home`, `switcher`, `care`, `addPet`.
**web:** `footer`, `globalError`.

Each declared section must be **100% covered** by that locale's dictionary; any key **outside** a
declared section is a test failure. This gives a real, complete, measurable machine-translated
body of copy with no half-translated screens and no unbounded executor workload.

**Safety pinning is expressed as the complement of the declared sections**, so the two lists can
never drift: `SAFETY_PINNED_PREFIXES` is every top-level key of the English tree that is **not**
in `TRANSLATED_SECTIONS` — which by construction includes `check.`, `chat.`, `medForm.`,
`timeline.`, `privacy.`, `servicesPreview.`, `paywall.`, `upsell.`, `breedGuide.`, `intake.`,
`notifications.`, `weight.`, `agenda.`, `feedback.`, `updateGate.`, `updateReady.`,
`upgradeBanner.`, `healthLogPhoto.`, and on web `disclaimer`, `legal.`, `landing.`, `foodPage.`,
`layout.`. The list is materialised explicitly in the file (not computed) **and** a test asserts
it equals the computed complement — belt and braces, so adding a new English section can never
silently become translatable.

### 2.6 Date / number / unit localization (the AC3 surface)

`apps/mobile/src/i18n/format.ts`
```ts
/**
 * Calendar-date display. `en` is PINNED to the app's existing ISO YYYY-MM-DD convention
 * (D5) — changing English date presentation is a product decision, not an i18n scaffold
 * decision, and would churn frozen snapshots. Every other locale formats via Intl with a
 * FIXED UTC time zone so output is deterministic in CI.
 */
export function formatEntryDate(iso: string, locale: LocaleId): string;
/** Locale-correct decimal separator; fixed fraction digits; grouping-free by domain (F11). */
export function formatDecimal(value: number, locale: LocaleId, fractionDigits?: number): string;
```
Wiring (only where `en` output is provably unchanged):
* `apps/mobile/src/checks/check-history.ts#formatCheckDate` → delegates to `formatEntryDate(iso, getActiveLocale())`. For `en` it still returns `new Date(iso).toISOString().slice(0,10)`.
* `apps/mobile/src/weight/weight-units.ts#formatWeight` → gains an optional `locale` parameter defaulting to `"en"` and uses `formatDecimal`. **A test asserts byte-equality with the old `toFixed(1)` output across the whole legal domain** (`WEIGHT_MIN_GRAMS`..`WEIGHT_MAX_GRAMS`, both units).

**Not wired (audit only, recorded in `docs/I18N.md` and in the founder delta):**
`app/care-plan/[petId].tsx:35` (a date *input* value, not display), the
`Intl.DateTimeFormat().resolvedOptions().timeZone` call sites (timezone, not formatting), and the
raw-number interpolations in `agenda.queuedBanner` / `activity.today.*` / `intake.maxSelectionsHint`
(they interpolate small counts inside pluralized **English** templates; correct pluralization for
es/pt/hi needs a plural-rule engine, which is out of card scope — R2/founder delta), plus web's
hardcoded USD price strings.

### 2.7 Pseudo-locale leak test (AC1) and RTL smoke (AC2)

**Mobile (rendered — the strong proof).** `pseudo-locale-leak.test.tsx` sets
`process.env.EXPO_PUBLIC_I18N_LOCALE = "en-XA"`, `jest.resetModules()`, then `require`s each of
the **3 core screens**: Home tab (`app/(tabs)/index.tsx`), Check Result
(`app/check/result/[checkId].tsx`), Chat (the chat screen route — the executor takes the exact
path and the mock set from the existing `home-screen.test.tsx`, `check-result-snapshot.test.tsx`,
`chat-screen-snapshot.test.tsx`). It walks the rendered tree, collects every text node, and
asserts each node is one of:
1. pseudo-transformed (`isPseudoTransformed`), **or**
2. a value the *test itself* supplied as fixture data (pet name, ISO date, numeric string) — an explicitly enumerated `DYNAMIC_FIXTURE_VALUES` array, **or**
3. containing no Unicode letter at all (`/^\P{L}*$/u` — icon glyphs, separators, digits).

Anything else is a hardcoded literal → fail, with the offending text in the failure message.

**Mobile + web (static — the CI breadth check).** `hardcoded-string-scan` walks
`apps/mobile/app/**/*.tsx` + `apps/mobile/src/components/**/*.tsx` (web: `apps/web/app/**/*.tsx`)
and flags JSX text nodes containing ≥3 consecutive Unicode letters. Findings are cleared by an
**exact-match allowlist** in the T097 `EXEMPTIONS` shape (`{ file, text, why }`) with a pinned
count. **T110 may not change any rendered copy to clear a finding** — copy changes are a §7
review surface and are out of scope; every finding is either genuinely non-user-facing (and
allowlisted with a reason) or reported to the founder.

**Web (resolver-level, F7).** `pseudo-locale.spec.ts` asserts `getStrings("en-XA")` transforms
**100%** of the web tree's leaves (compare `collectLeafPaths` before/after; every string leaf and
every function-leaf result is pseudo-marked).

**RTL smoke (AC2).** `rtl-smoke-snapshot.test.tsx` renders the same 3 screens under
`EXPO_PUBLIC_I18N_LOCALE = "ar-XB"` and writes **new** snapshots to a **new** file
(`__tests__/__snapshots__/rtl-smoke-snapshot.test.tsx.snap`). It additionally asserts
`getTextDirection("ar") === "rtl"`, `getTextDirection("ar-XB") === "rtl"`, and that no rendered
text node is an untransformed English strings leaf.

**Honest limitation, stated in the test file's header comment and in `docs/I18N.md`:** jest
renders no native layout, so these snapshots prove *copy resolution + crash-free render under an
RTL-tagged locale*, not visual mirroring. T110 deliberately does **not** call
`I18nManager.forceRTL` (it requires an app reload and would change layout for real users of a
locale we do not serve). Physical-direction NativeWind classes (`ml-*`, `pl-*`, `text-left`,
`flex-row`) across the app are inventoried in `docs/I18N.md` as the follow-up that must land
before any RTL locale is served.

## 10. Founder delta

* **Nothing ships in a new language.** Every non-English locale is `reviewed: false` and is
  mechanically forced back to English at serve time. `es`, `pt-BR` and `hi` dictionaries exist and
  are complete for their declared sections, but a user in Madrid still sees English today.
* **The human-review pipeline you must run before flipping any locale to `reviewed: true`:**
  1. A **native-speaker human translator** reviews that locale's dictionary end to end.
  2. Because our guidance is health-adjacent, a **veterinarian (or clinically-qualified reviewer)

     translated at all** and must be translated *by a human first*, since we deliberately refuse to

  3. The T038 safety detector **works only in English.** Serving a locale means either commissioning
     language-specific detector patterns or accepting that the automated §7 net does not cover that
     locale. This is a real, recurring cost per language and should be budgeted as such.
  4. Only then flip `reviewed: true`, in its own task with its own §7 review.

  physical-direction styles (`ml-*`, `pl-*`, `text-left`, `flex-row`) throughout, inventoried in

  flow. T110 delivers the smoke test, not the mirroring.
* **Two engineering follow-ups you may be asked to fund:** (a) per-request locale negotiation on the
  Next.js site (today the web locale is per-process — fine while English-only, blocking for
  multilingual SEO); (b) a plural-rules engine — Hindi and Arabic do not use English-style two-form
  plurals, so our hand-rolled `n === 1 ? … : …` templates will be wrong for them.
* **No language switcher exists, deliberately** — offering one while only English is served would
  be a broken promise.
* **User-visible change in this task: essentially zero.** English output is byte-identical
