## 1. Design decisions (each one is a scrutiny target — see §6 Risks)

- **D1 — Split: pure payload builders in `packages/analytics/src/dashboards/`, thin CLIs in
  `apps/api/scripts/`.** Builders are pure functions returning JSON-serialisable payloads,
  unit-tested by the fast node jest of `packages/analytics`. CLIs own only env reading,
  `fetch`, the upsert flow, and exit codes.
- **D2 — Compile-time drift guard by TYPE, plus a runtime one.** Every funnel/retention step
  in the builders is typed `AnalyticsEventName` (imported from `../events`), so an invented
  event name is a `tsc` failure. A spec additionally parses `events.ts` source text and
  asserts every step name is present there (guards against `AnalyticsEventName` widening).
- **D3 — CLIs live in `apps/api/scripts/` and run under tsx via a dedicated
  `apps/api/scripts/tsconfig.json`** overriding `@bombaypetcompany/analytics` to
  `../../../packages/analytics/dist/index.cjs` (SEEDER-1 precedent). Reason: tsx exists only
  in apps/api / apps/mobile, and this avoids any dependency install / lockfile change.
- **D4 — `scripts` is added to `apps/api/tsconfig.json` `include` AND to
  `apps/api/tsconfig.build.json` `exclude`.** The include gives `pnpm typecheck` real coverage
  of the CLIs; the build exclude is MANDATORY — without it `nest build` widens the inferred
  `rootDir` from `src` to `apps/api` and emits `dist/src/main.js`, breaking the api start path.
- **D5 — `--dry-run` prints the exact payloads and exits 0; keyless real runs exit 2** with a
  message naming the missing env vars. This gives the executor runnable keyless evidence and
  the founder a review step before any write to a live project.
- **D6 — Idempotent upsert by NAME.** `GET` existing insights/dashboards/alert-rules, match on
  the exact committed `name`, `PATCH`/`PUT` when found, `POST` when not. Re-running never
  creates duplicates.
- **D7 — New env names are ops-only and never enter the app runtime env schema.**
  `POSTHOG_PERSONAL_API_KEY`, `POSTHOG_PROJECT_ID`, `POSTHOG_API_HOST`, `SENTRY_AUTH_TOKEN`,
  `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_API_HOST` are read by the CLIs directly from
  `process.env`; they are **not** added to `apps/api/src/config/env.schema.ts` or
  `packages/config` (they must never become required boot config).
- **D8 — PostHog API host is a separate variable.** `POSTHOG_HOST`
  (`https://us.i.posthog.com`) is the *ingestion* host; the insight/dashboard API lives on the
  app host (`https://us.posthog.com`). Reusing `POSTHOG_HOST` would produce confusing 404s, so
  `POSTHOG_API_HOST` is its own var with its own default and a doc note.
- **D9 — Sentry crash-free alert is a metric alert rule**
  (`POST /api/0/organizations/{org}/alert-rules/`) with `dataset: "metrics"`,
  `aggregate: "percentage(sessions_crashed, sessions) AS _crash_rate_alert_aggregate"`,
  `thresholdType: 1` (below), `timeWindow: 60`, one trigger `label: "warning"`,
  `alertThreshold: 99`, `resolveThreshold: 99.5`, `environment` from env, `projects:
  [SENTRY_PROJECT]`. `actions` is left empty ⇒ the founder attaches the notification target
  in the UI (documented as `[FOUNDER-4]`).

## 6. Risk register (top 5 — checker: scrutinise these first)

1. **R1 (highest) — the `apps/api/tsconfig.json` include change can silently relocate build
   output.** Adding `"scripts"` to `include` without adding it to `tsconfig.build.json`
   `exclude` widens the inferred `rootDir` to `apps/api/` and moves `dist/main.js` →
   `dist/src/main.js`, breaking the api start command. Mitigation: both edits in one step
   (step 9), a spec asserting both (AC1-c), and the `ls apps/api/dist/main.js` gate. *Safe
   fallback if the checker prefers: drop the include change and accept that
   `apps/api/scripts` is untypechecked (the `prisma/seed.ts` precedent). Decision made in
   favour of coverage.*
2. **R2 — PostHog insight `query` schema is version-sensitive.** The `query`/InsightVizNode
   shape (vs the legacy `filters` shape) differs across PostHog versions and cannot be
