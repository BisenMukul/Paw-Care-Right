# Plan — T084: Breed hub content (`packages/data/breed-guides`)

## Objective (from card)
For the top 50 breeds, ship a structured care profile (temperament summary, exercise needs,
common-condition **awareness** list phrased as "Talk to your vet about…", grooming cadence) in
`packages/data/breed-guides`, gated by a `reviewed: boolean` flag. **Only `reviewed: true` guides
ship.** Deliver the generation script + **5 hand-reviewed exemplars** now; the other 45 land as
`reviewed: false` drafts for post-C3 review.
**Accept:** (AC1) schema-valid · (AC2) only reviewed guides are rendered/exposed (test) ·
(AC3) no dosage/diagnosis language — the T038 detector run as a lint over the **entire** dataset.

---

## Safety statement (PRODUCT_SPEC §5 / CLAUDE.md §7 — read before step 1)

1. **No §5 surface is touched.** This card adds **zero** files under `apps/**`, `packages/types/**`,
   `apps/api/prisma/**`, `packages/ai/src/rules/**`, `packages/ai/src/safety/**`,
   `packages/ai/src/triage/**`, `packages/ai/src/chat/**` or `packages/ai/src/evals/**` (the detector
   is **imported**, never edited). Disclaimers, the Emergency interstitial, hotlines, red-flag rules,
   the output gate and the fail-upward fallbacks are all untouched. **Not a SAFETY-ESCALATION card.**
2. **This dataset is static content, not AI output at runtime.** Nothing here is called by a request
   path. It is prose that a human reads in-app (T087). Its only safety weight is *what the words say*.
3. **Condition content is awareness-only, never clinical.** Every `commonConditionAwareness` item is a
   *question to ask a vet*, enforced structurally: the schema requires the string to start with the
   exact constant `VET_PROMPT_PREFIX = "Talk to your vet about "`. No condition is ever asserted about
   the reader's pet, no prevalence/likelihood claim, no test/treatment recommendation, no prognosis.
4. **Zero medication surface.** No drug names, no dosages, no numerals with mass/volume units, no
   administration verbs. Enforced by the real T038 `scanUnsafeText` over every string of every guide —
   **including the 45 unreviewed drafts** (AC3 says "over dataset", and an unreviewed row is still
   committed text a future reviewer could rubber-stamp).
5. **"diagnos*" is banned outright** (detector `DIAGNOSIS_LANGUAGE`), as are the harm-enabling tokens
   the detector knows (`declaw`, `ear-crop`, `tail-dock`, `sedate`, `fight` + conditioning cues).
   Cat grooming copy must therefore not mention declawing even to condemn it — say nothing.
6. **A model may never mark its own output reviewed.** The generator forces `reviewed: false` and
   `provenance.generatedBy` on every written draft, *discarding* any `reviewed` field the provider
   emitted (test M4). Review is a human act recorded post-C3.
7. **Review honesty.** `reviewedBy` for the 5 exemplars is `"content-editor"` — an editorial pass,
   **not** veterinary sign-off. A test forbids any `reviewedBy` matching `/vet|dvm|dr\.?|veterinar/i`
   so the dataset can never *imply* a vet approved it. Veterinary review is a C3/T105 item.
8. **Fail upward in the generator.** A provider draft that fails Zod **or** trips the detector is
   discarded and the deterministic template draft is kept — never partially accepted, never retried
   into a guess.

## Key decisions (each is a design choice — restated as risks at the end)

- **D1 — The dataset lives in `packages/data/src/breed-guides/` as two JSON files
  (`dogs.json`, `cats.json`) with species attached by the loader.** Byte-for-byte the T022 breeds
  precedent (`packages/data/src/breeds/index.ts:1-13`: `import dogsRaw from "./dogs.json"` →
  `schema.parse({...row, species: "DOG"})` → `Object.freeze`). JSON (not TS literals like `toxins/data/*`)
  because a **script writes these files**; machine-writing JSON is safe, machine-writing TS source is not.
- **D2 — Guide identity is the pair `(species, slug)`, never the slug alone.** Verified: `mixed-unknown`
  exists in **both** `dogs.json` and `cats.json`, so slugs are unique only *within* a species. All
  accessors take `(species, slug)`. `mixed-unknown` gets **no** guide (nothing true can be said about it).
- **D3 — The generator lives in `packages/ai/src/content/`, not in `packages/data`.**
  `packages/data` is a leaf package (`packages/data/package.json` deps: `zod`, `@pawcareright/types`
  only) and **`packages/ai` already depends on `@pawcareright/data`** — so `data → ai` would be a
  dependency cycle. The generator needs *both* the Ollama text provider **and** `scanUnsafeText`, both
  of which live in `packages/ai`. This is the exact precedent of
  `packages/ai/src/rules/emergency-payload-parity.spec.ts:5-11` ("the only cycle-free home able to
  import both"). The **detector-lint spec** lives there for the same reason.
- **D4 — Two generation modes, one code path: `template` (default, deterministic, offline) and
  `provider` (opt-in, Ollama Cloud).** Mode is resolved by the **existing** `resolveMode(process.env)`
  (`packages/ai/src/evals/harness.ts:27-36`) — no new env var: a genuine `OLLAMA_CLOUD_API_KEY` +
  `AI_TEXT_PROVIDER=ollama` ⇒ `"real"` ⇒ provider drafting; otherwise `"fake"` ⇒ template drafting. CI
  and the loop have no key, so the script is always deterministic here and the committed bytes are
  reproducible. Provider output is *drafting assistance only*: it still goes through Zod + detector +
  forced `reviewed:false` (D-safety 6/8).
- **D5 — The 45 unreviewed drafts are deliberately GENERIC and near-identical.** Template copy is
  derived only from facts the breeds dataset actually holds (species, `sizeClass`, weight band) and
  makes **no breed-specific medical-adjacent claim**. Fabricating 45 breed-specific condition lists
  without review is the unsafe alternative; the card explicitly parks them for post-C3 review, and
  `publishedBreedGuides` never contains them. (Risk R2.)
- **D6 — Content model = four typed fields, no free-form markdown body.** T087's "markdown-ish
  renderer for dataset content blocks" renders these four fields as sections. A free-text body would
  be un-lintable prose and scope creep.
- **D7 — Exported surface: `publishedBreedGuides` (reviewed only) is the primary export;
  `allBreedGuides` (all 50) is the explicitly-named audit/tooling export.** `getBreedGuide(species,
  slug)` resolves **only** published guides (returns `undefined` for a draft). `allBreedGuides` must
  stay exported because the AC3 lint must scan drafts too, and T105 needs the reviewed-flag inventory.
- **D8 — The 50 slugs are pinned in-repo** as `TOP_DOG_BREED_GUIDE_SLUGS` (38) +
  `TOP_CAT_BREED_GUIDE_SLUGS` (12) — every slug below was **verified to exist** in the T022 dataset by
  the planner. Tests assert existence, uniqueness, and guide↔list completeness in both directions.
- **D9 — The 5 exemplars** (globally popular, both species, all verified present):
  `labrador-retriever`, `golden-retriever`, `german-shepherd` (dogs), `maine-coon`, `persian` (cats).
- **D10 — Pure logic vs. I/O is split.** `breed-guide-draft.ts` is pure (template builder, provider-draft
  parse+gate, merge) and fully unit-tested; `generate-breed-guides.ts` is a thin CLI (read → merge →
  write → stdout summary), mirroring `harness.ts` vs `run.ts`.

## Contracts (executor must match exactly)

```ts
// packages/data/src/breed-guides/schema.ts
export const VET_PROMPT_PREFIX = "Talk to your vet about ";

export const EXERCISE_LEVELS = ["LOW", "MODERATE", "HIGH", "VERY_HIGH"] as const;
export const GROOMING_FREQUENCIES = ["DAILY", "SEVERAL_TIMES_WEEKLY", "WEEKLY", "MONTHLY"] as const;
export const GENERATED_BY = ["TEMPLATE", "PROVIDER", "HUMAN"] as const;

export const vetAwarenessPromptSchema = z
  .string()
  .min(VET_PROMPT_PREFIX.length + 10)
  .max(220)
  .refine((s) => s.startsWith(VET_PROMPT_PREFIX), { message: "must start with VET_PROMPT_PREFIX" });

export const breedGuideRowSchema = z.strictObject({
  slug: slugSchema,                                   // from ../breeds/schema
  temperament: z.string().min(40).max(400),
  exerciseNeeds: z.strictObject({
    level: z.enum(EXERCISE_LEVELS),
    narrative: z.string().min(40).max(400),
  }),
  commonConditionAwareness: z
    .array(z.strictObject({ topic: z.string().min(3).max(60), prompt: vetAwarenessPromptSchema }))
    .min(2)
    .max(6),
  groomingCadence: z.strictObject({
    frequency: z.enum(GROOMING_FREQUENCIES),
    narrative: z.string().min(40).max(400),
  }),
  reviewed: z.boolean(),
  provenance: z.strictObject({
    generatedBy: z.enum(GENERATED_BY),
    model: z.string().min(1).optional(),
    reviewedBy: z.string().min(1).optional(),
    reviewedAt: z.string().regex(/^\d{4}-\d{2}-\d{2}$/).optional(),   // date only, no clock
  }),
})
  // reviewed === true  <=>  reviewedBy AND reviewedAt present (both directions)
  .refine((g) => g.reviewed === (g.provenance.reviewedBy !== undefined && g.provenance.reviewedAt !== undefined),
          { message: "reviewed must be true iff reviewedBy and reviewedAt are both present" });

export const breedGuideSchema = /* row + species: breedSpeciesSchema */;
export type BreedGuideRow = z.infer<typeof breedGuideRowSchema>;
export type BreedGuide = z.infer<typeof breedGuideSchema>;

// packages/data/src/breed-guides/index.ts
export const allBreedGuides: readonly BreedGuide[];        // 50, dogs then cats, parse-at-load + frozen
export const publishedBreedGuides: readonly BreedGuide[];  // === allBreedGuides.filter(g => g.reviewed)
/** Published guides ONLY. Returns undefined for an unreviewed draft or an unknown pair. */
export function getBreedGuide(species: BreedSpecies, slug: string): BreedGuide | undefined;

// packages/ai/src/content/breed-guide-draft.ts  (pure)
export function buildTemplateDraft(breed: Breed): BreedGuideRow;   // deterministic, reviewed:false, generatedBy:"TEMPLATE"
export type ProviderDraftOutcome =
  | { ok: true; row: BreedGuideRow }
  | { ok: false; reason: "unparsable" | "schema" | "unsafe"; findings?: string[] };
/** extract-json -> Zod -> scanUnsafeText over every string -> force reviewed:false +
 *  provenance {generatedBy:"PROVIDER", model} and DROP any provenance/reviewed the model emitted. */
export function parseProviderDraft(raw: string, breed: Breed, model: string): ProviderDraftOutcome;
/** Replaces a row only when the EXISTING row has reviewed !== true. Keyed by slug within one species
 *  file. Output order = the pinned top-slug order. Idempotent: merge(merge(a,b),b) deep-equals merge(a,b). */
export function mergeBreedGuides(existing: readonly BreedGuideRow[], drafts: readonly BreedGuideRow[]): BreedGuideRow[];
```

**CLI behaviour (`generate-breed-guides.ts`).** `findRepoRoot()` → read the two JSON files (missing file
⇒ `[]`) → for each pinned slug resolve its `Breed` from `allBreeds` (missing slug ⇒ hard error, non-zero
exit) → build a draft (`resolveMode(process.env) === "real"` ⇒ `getTextProvider().generate(...)` with
the prompt, then `parseProviderDraft`; **any** non-`ok` outcome or thrown `ProviderError` ⇒ fall back to
`buildTemplateDraft` and count it) → `mergeBreedGuides` per species → write
`JSON.stringify(rows, null, 2) + "\n"` → print `written/skipped(reviewed)/provider-rejected` counts.
It **never** flips `reviewed`, never deletes a row, and never touches a file outside
`packages/data/src/breed-guides/`.

**Deterministic template mapping (pin exactly; drives `buildTemplateDraft`).**
`exerciseNeeds.level`: CAT ⇒ `MODERATE`; DOG by `sizeClass`: `TOY`/`SMALL` ⇒ `MODERATE`,
`MEDIUM`/`LARGE` ⇒ `HIGH`, `GIANT` ⇒ `MODERATE`, `UNKNOWN` ⇒ `MODERATE`.
`groomingCadence.frequency`: `WEEKLY` for every template draft.
`commonConditionAwareness`: exactly two generic items, e.g.
`{ topic: "Routine wellness checks", prompt: "Talk to your vet about which routine wellness checks
suit this pet's age, size and lifestyle." }` and one on weight/body-condition — **both breed-agnostic**.
Template prose must be *true of any individual of that species/size band* (e.g. "temperament varies far
more between individuals than between breed labels; early socialisation and daily routine matter most").

## Content authoring rules for the 5 exemplars (CHECKER will grep this hard)

Write real, useful, honest copy — and obey every line below, because the detector is a hard gate:
- **Never** the substring `diagnos`. Never a drug/brand name. Never a number followed by
  `mg|ml|mcg|g|kg|iu|tsp|tbsp` (so: no "35 kg", no "60 g" — say "large-breed", "a full meal").
- Never `give|administer|dose|take` within ~40 chars of `every N hours/days` (say "brush twice a week",
  "daily walks"). Minutes/weeks/years in words or with `minute(s)`/`week(s)` are safe.
- Never `declaw`, `ear crop`, `tail dock`, `sedate/sedation`, `euthan*`, `fight/fighting`, `bait`,
  `surgery ... at home`, `DIY`.
- Awareness items name a **body system or life-stage topic**, phrased as a vet conversation:
  e.g. `topic: "Hips and elbows"`, `prompt: "Talk to your vet about joint screening and what activity
  suits a growing large-breed dog."` — never "your dog probably has…", never a likelihood claim, never
  a test/treatment instruction.
- Grooming/exercise copy is husbandry, not medicine. Coat, brushing, nail and ear *checks* are fine;
  cleaning products, ear drops and any product recommendation are not.
- 3–5 awareness items per exemplar; `provenance` = `{ generatedBy: "HUMAN", reviewedBy: "content-editor",
  reviewedAt: "<the commit date, YYYY-MM-DD>" }`, `reviewed: true`.

  daily.")` returns ≥1 finding.
- **"positive control: a planted diagnosis string IS flagged"** — `scanUnsafeText("This is a diagnosis
  of hip dysplasia.")` returns ≥1 finding.

## Risks & the decisions the planner made (for the checker)

- **R1 (D3) — the "generation script" lives in `packages/ai`, not next to the data it writes.** Forced
  by the dependency graph (`ai → data`; `data → ai` cycles) and by the fact that the script must call
  *both* the provider and the detector. Precedent: `rules/emergency-payload-parity.spec.ts`. If the
  checker prefers `packages/data/scripts/`, note that `packages/data` has neither a provider nor a
  runner dependency and would need a new dev dependency (`tsx`) — rejected under §2 rule 7.
- **R2 (D5) — the 45 unreviewed drafts are generic and largely interchangeable.** A reviewer could call
  this filler. The alternative — 45 machine-written breed-specific condition lists — is medical-adjacent
  text nobody checked, which is precisely what the `reviewed` flag exists to prevent. They never reach a
  user (AC2 tests), and T105 audits the inventory. If the founder wants real drafts before C3, run the
  script with a live `OLLAMA_CLOUD_API_KEY` (D4) — every draft still lands `reviewed:false`.
- **R3 (AC2 wording) — "app renders only reviewed guides (test)" is proven at the data-accessor layer,
  not in a rendered screen,** because the screen (T087) does not exist yet and building it here would be
  scope creep on a card that says "content". Mitigation: `publishedBreedGuides` is the primary export,
  `getBreedGuide` refuses drafts, and the drafts are only reachable through the deliberately verbose
  `allBreedGuides`. **Residual risk:** T087 could import `allBreedGuides` by mistake — that must be an
  explicit T087 acceptance item (recorded in the journal hand-off).
- **R4 (D4) — the provider path is exercised only through `FakeTextProvider`.** No live Ollama call runs
  in CI (there is no key), so real-model output quality is unproven — same class as the harness's
  `resolveMode` fake default. Mitigation: every provider draft is Zod-gated, detector-gated and forced
  to `reviewed:false`, so the worst case is a rejected draft, never unsafe shipped content.
- **R5 — detector false positives on husbandry prose are likely on the first pass** (e.g. `per kg`, any
  `\d+ kg`, `fight` near `training`, `declaw`). This is a *feature*: the fix is always the string. The
  content rules section lists the traps so the executor does not discover them one failing run at a time.
- **R6 (D2) — `(species, slug)` identity changes the shape a naive consumer expects.** Verified
  necessary: `mixed-unknown` exists in both breed files. Accessors therefore require a species argument;
  a slug-only helper is deliberately not provided.
- **R7 — writing generated JSON by hand-rolled `JSON.stringify(…, null, 2)`** may drift from Prettier's
  formatting if a format check is ever added to `lint` (today `packages/data` runs ESLint only, which
  does not lint `.json`). Two-space + trailing newline matches Prettier's default for JSON, so the drift
  risk is low; flagged rather than solved.
- **R8 — adding a tsup entry to `packages/ai` emits an extra `dist/content/*.js` on every build.**
  Harmless (the existing `dist/evals/run.js` sets the precedent) and it is what makes the script runnable
  with no new dependency, but it does mean `pnpm build` output grows. The CLI is not exported from
  `src/index.ts`, so nothing can import it accidentally.
- **R9 — `reviewedAt` is a date string, not a `Date`.** Chosen for JSON round-trip stability and to keep
  the dataset diff-clean; no timezone semantics are needed for an editorial timestamp.
