## Design decisions (minimum set — scrutinise every one)

- **D1. `updates.url` is derived from a single module-scope `EAS_PROJECT_ID` const in
  `app.config.js`**, used by both `extra.eas.projectId` and `updates.url`
  (`https://u.expo.dev/<id>`), so the two can never drift. The UUID stays the existing pre-REBRAND-1
  value with the existing comment extended: the founder's EAS project re-create becomes a **one-line**
  edit that fixes both. No new UUID is invented.
- **D2. `runtimeVersion: { policy: "fingerprint" }`** at the top level of the Expo config (not
  per-platform), per OTA_UPDATES §1 and the card's literal text.
- **D3. Version pinned to `~57.0.7`** from `bundledNativeModules.json` (F1), i.e. exactly what
  `npx expo install expo-updates` would resolve — the plan prefers the deterministic
  `pnpm --filter … add expo-updates@~57.0.7` and treats `expo install` as a cross-check only, because
  `expo install` shelling out inside a pnpm workspace is the riskier of the two.
- **D4. `updates.fallbackToCacheTimeout: 0` and `updates.checkAutomatically: "ON_ERROR_RECOVERY"` are
  set now, in T113, not deferred to T114.** Rationale: both keys land in the native
  `Expo.plist`/`AndroidManifest.xml`, so they are *fingerprint input* — changing them in T114 would
  change the fingerprint and invalidate every binary built in between (exactly the failure mode §1
  exists to prevent). Leaving the SDK default (`ON_LOAD`, blocking launch on a network check) would
  also ship a config that contradicts OTA_UPDATES §3's non-blocking 3s-budget contract. T114 still
  owns all *JS* flow logic; this card adds none.
- **D5. `OtaInfo` is a local mobile interface in `src/observability/ota-info.ts`, not a Zod schema in
  `packages/types`.** It crosses no API boundary, so putting it in `packages/types` would trigger the
  dist-rebuild landmine for zero benefit.
- **D6. Injectable loader (purchases.ts precedent), not a `jest.setup.ts` global mock**, so the
  "module absent (Expo Go / jest)" path is directly tested and no shared setup file is touched.
- **D7. The fingerprint tooling lives in `apps/mobile/scripts/fingerprint-diff.sh`**, invoked both by
  CI and by the local journal-evidence run — one code path, no CI-only shell.
- **D8. The CI job is informational-by-construction**: it fails only if the *tooling* fails, never
  because the fingerprint changed (a legitimate, expected event); the verdict goes to
  `$GITHUB_STEP_SUMMARY` + an uploaded artifact. It is `pull_request`-only (the card says "per PR").
- **D9. The "native-dep-change fixture" evidence is captured in-tree by ordering, not by a fake
  branch:** the baseline fingerprint is generated **before** `expo-updates` is installed and the
  post-change fingerprint after — installing `expo-updates` *is* a real native-dep change, so
  `fingerprint:diff pre.json current.json` yields genuine, non-fabricated diff output for the journal.
  No PR, no second worktree, no invented fixture. (See step 2 — it must run FIRST.)

### Phase C — the hook

7. **Create `apps/mobile/src/observability/ota-info.ts`** — pure, no React:
   - `export interface OtaInfo { isEnabled: boolean; updateId: string | null; channel: string | null; runtimeVersion: string | null; isEmbeddedLaunch: boolean; }`
   - A narrow `interface UpdatesNative` covering only the fields read (`isEnabled`, `updateId`,
     `channel`, `runtimeVersion`, `isEmbeddedLaunch`), each optional so a partial mock fixture stays
     valid (mirrors `PurchasesNative`'s optional-method note).
   - `export type UpdatesLoader = () => UpdatesNative | null;` plus a `defaultLoader` that
     lazy-`require`s `"expo-updates"` inside try/catch and returns `null` on failure, using the same
     `// eslint-disable-next-line @typescript-eslint/no-require-imports -- JUSTIFIED: …` form as
     `purchases.ts`/`sentry.ts` (F6).
   - `export function readOtaInfo(loader: UpdatesLoader = defaultLoader): OtaInfo` — returns the
     all-absent shape (`{ isEnabled: false, updateId: null, channel: null, runtimeVersion: null,
     isEmbeddedLaunch: true }`) when the loader yields `null` **or throws**, and otherwise normalises
     each field (non-string → `null`, non-boolean → its documented default). Empty-string `channel`/
     `updateId` normalise to `null`: EAS reports `""` vs `null` inconsistently across
     dev-client/embedded launches and a falsy channel must never masquerade as a real one.
   - No `console.*`, no throwing path, strict TS, no `any`.
8. **Create `apps/mobile/src/hooks/use-ota-info.ts`** —
   `export function useOtaInfo(loader?: UpdatesLoader): OtaInfo` returning
   `useMemo(() => readOtaInfo(loader), [loader])`. These values are fixed for the process lifetime
   (boot-time tags), so no state, no effect, no polling. Doc comment cites the card and names T114
   (update flow) and T117 (Sentry release tags / PostHog `ota_*`) as the consumers, and states that the
   hook renders nothing and adds no user-facing string.
