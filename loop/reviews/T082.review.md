## 11. Findings

**Finding 1 — [MEDIUM, plan defect — not an executor defect] The plan's M1 mutation is a no-op, so the
overlap scan would have been "proven" vacuously.** `output-gate.ts:149` uses
`(this.releasedTail + text).slice(-CHAT_SCAN_OVERLAP_CHARS)`. With the constant set to `0`,
`slice(-0)` === `slice(0)` in JavaScript (`node -e 'console.log("abcdef".slice(-0))'` → `"abcdef"`),
so `releasedTail` retains the **entire** released stream and the gate becomes strictly *stricter*.
I confirmed empirically: M1 failed only the `>= 96` lower-bound assertion and `pnpm test:ai-evals`
still exited 0. Had the executor run the plan's matrix as written, it would have reported M1 "passing"
while proving nothing. I substituted M1b (removing `releasedTail` from the scan input, per my brief),
which failed 3 tests and the eval exit code. **Shipped code is correct** (128, with a `>=96` floor
test); the failure mode here is fail-*safe*. Action: none on the code; the planner should not reuse the
`= 0` form for a `slice(-n)` constant.

**Finding 2 — [LOW] `runGatedStream`'s failure branches are covered cross-package, not at the gate
level.** `output-gate.ts:191-193` (abort), `:209-212` (tail flag/release) and `:216-239`
(`empty_completion`, `provider_error`) are uncovered by `packages/ai`'s own specs — 83.07% stmts, above
the §6 bar but the thinnest number in the diff. They *are* exercised behaviourally by
`chat.service.spec.ts` (F2 empty-completion, provider-error incident) and by T081's e2e, so the
behaviour is proven; the proof just lives in another workspace. Two gate-level unit tests would
localise it. Not blocking.

**Finding 3 — [LOW] `chat-load.ts` error paths are unexercised** (79.48% stmts, **30% branch**): the
`INVALID_YAML` catch, the schema-failure aggregation, the duplicate-id check and the `chat-` prefix
check never run. The plan did not require a `chat-load.spec.ts`. This is authoring-time eval tooling,
not a runtime safety surface, so the blast radius is a confusing error message for a future case
author. Not blocking.

**Finding 4 — [LOW, bookkeeping] CLAUDE §8 items are incomplete.** `loop/journal.md` has **no T082
entry** (including the plan-mandated "no new dependencies" note) and `loop/loop-state.json` is at HEAD
— correct right now, since the orchestrator reverted the executor's premature edit, but both still
need to be written before the task is done, along with the conventional commit
`fix(chat): T082 …`. Additionally there are now **7** untracked `loop/eval-reports/*.md`: three from
the executor (`21-09-06`, `21-11-03`, `21-13-11`) and four from my verification runs (`21-16-46`,

**Finding 5 — [INFO] The `HARM_B` / `DOSE_FREQ` quantifiers are theoretically unbounded.** `[a-z]*`
