### Allowlist adjudication — GHSA-mh99-v99m-4gvg (brace-expansion, CVE-2026-14257, CVSS 7.5 AV:N/A:H)

I adjudicated the single suppression on four independent axes rather than accepting the recorded log.

1. **"Fix exists ONLY as 5.0.8" — CONFIRMED.** The advisory's own machine data in my baseline audit JSON:
   `vulnerable_versions: "<=5.0.7"`, `patched_versions: ">=5.0.8"` — a single unqualified range, no
   per-major carve-out. Corroborated against the npm registry version-time table: the newest 1.x release
   is **1.1.16 (2026-07-08)**, published 15 days *before* the fix (**5.0.8, 2026-07-23**); no 1.x/2.x/3.x/4.x
   release exists after it, so no backport exists as of today. The orchestrator's earlier
   "1.1.12/2.0.2/3.0.1 are patched" hypothesis is refuted by the registry: all three were published
   2025-06-11 and are *older* than what is already resolved — a downgrade, not a patch.
2. **"Tree-wide force breaks the web build with `expand is not a function`" — CONFIRMED MECHANICALLY**
   (stronger than re-running the destructive override, and non-destructive):
   - `brace-expansion@1.1.16` → `typeof module.exports === "function"` (directly callable).
   - `brace-expansion@5.0.8` → `typeof module.exports === "object"`, keys `[EXPANSION_MAX, EXPANSION_MAX_LENGTH, expand]` — **not callable**.
   - `minimatch@3.1.5/minimatch.js:10` `var expand = require('brace-expansion')`, `:271` `return expand(pattern)`.
   Forcing 5.0.8 into that node therefore produces exactly the recorded verbatim error. `minimatch@3.1.5`
   declares `brace-expansion: ^1.1.7`; an override to `^5` is a forced incompatible major.
3. **Reachability — CONFIRMED, dev/build-time only.** The advisory's own `findings[].paths` list exactly two
   paths, both under a devDependency: `apps__api>@nestjs/cli>fork-ts-checker-webpack-plugin>minimatch>brace-expansion@1.1.16`
   (the suppressed one) and `apps__api>@nestjs/cli>glob>minimatch>brace-expansion@5.0.7` (now 5.0.8, fixed).
   Chain pins verified in `node_modules`: `@nestjs/cli@11.0.24` pins `fork-ts-checker-webpack-plugin: "9.1.0"`
   exactly, which requires `minimatch: "^3.0.4"`; `@eslint/config-array@0.21.2` requires `minimatch: "^3.1.5"`
   (the second consumer of the same frozen node, hence the ESLint-time failure). Nothing on this chain is
   in the built API image or reachable from a network request. Impact is DoS-only (C:N/I:N/A:H).
4. **Expiry + sync are enforced, not decorative** — proven by mutation, not by reading:
   - **CK1** empty `docs/security/audit-allowlist.json` → `security-ci-gate.spec.ts` RED with
     `{"kind": "undocumented-suppression"}` (1 failed / 15 passed).
   - **CK2** `expiresOn` backdated to 2026-07-24 → RED with `{"kind": "expired"}`.
   - **CK3** GHSA removed from `pnpm.auditConfig.ignoreGhsas` → **`pnpm audit --audit-level high` exits 1**
     (`Severity: 2 low | 2 moderate | 1 high`, no longer "ignored") **and** the sync test RED with
     `{"kind": "orphan-allowlist-entry"}`. This simultaneously proves the suppression is load-bearing and
     that `ignoreGhsas` is honoured **natively** by pnpm 10.34.3 — D1's stated verification obligation.
   All three restored byte-identical (`sha1sum -c` OK).
