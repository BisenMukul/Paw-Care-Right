### Finding 2 — LOW — wrong `.gitignore` attributed in notes §7
`loop/checkpoint-C3-notes.md:121-122` says the export dirs "are gitignored (`apps/mobile/.gitignore` `.perf/` pattern)". `apps/mobile/.gitignore` contains no `.perf/` pattern; the actual rule is the **root** `.gitignore:15` → `apps/mobile/.perf/`, which I confirmed with `git check-ignore -v`. ### Finding 3 — LOW — Apple/Play asymmetry in the IAP prerequisites
§5 includes `- [ ] **[FOUNDER]** Add Play license testers for IAP sandbox purchases, and configure RevenueCat's Play Store credentials` (notes:79), but §4 has no Apple-side counterpart: no App Store Connect *Paid Applications Agreement* / Agreements-Tax-Banking step, no subscription product creation, no Sandbox Apple ID testers, no RevenueCat App Store credentials.
Impact: does not block a build from becoming *installable* via TestFlight-internal, which is the card's literal scope, and RevenueCat setup is nominally owned by the standing C2 to-do that notes:79 itself cites. But since the Play side was included anyway, a founder working the list top-to-bottom will set up Play IAP sandbox and silently skip the Apple equivalent, and §9's "installable **and launchable**" end state implies a working paywall. Recommend one `[FOUNDER]` line in §4 mirroring notes:79. Not blocking.

### Finding 4 — LOW (advisory, non-blocking) — loop bookkeeping not yet done
`loop/loop-state.json` still records `"T101": {"status": "pending", "attempts": 0}` and `loop/journal.md` has no T101 entry. CLAUDE.md §8 lists both as Definition-of-Done items. Plan §1 items 6–7 make these conditional ("only if the executor is the one writing them"), and the commit itself is likewise still pending by design since I review the uncommitted diff — so this is a normal post-review step rather than a defect in the work. Flagged only so it is not forgotten before the commit.

### Finding 5 — LOW (observation, no action) — T9's weakest assertion
