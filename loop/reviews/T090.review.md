## 9. Findings

**F1 (non-blocking, fix-forward prescription) — the chat-path audit call site has no closed-set guard; a content plant there survives the whole suite.**

Checker-authored probe P2: `chat.service.ts:208` mutated to
`const detectorFlags = [...buildChatDetectorFlags(result.incident ?? undefined), dto.content];`
— i.e. the user's raw chat message text written into the `AiAuditLog.detectorFlags` column.
Result: **`src/chat` + `src/audit` + `test/chat.e2e-spec.ts` → 5 suites / 48 tests, ALL GREEN.** The leak was not caught.

Why this is **not** a fail of T090 as specified:
- The code **as shipped is clean**. `detectorFlags` on the chat path is `buildChatDetectorFlags(result.incident)` and nothing else, and that builder is mutation-proven content-free (`ai-audit.flags.spec.ts` "never returns free text" cases; the whole-set sweep).
- The two defences the plan *did* specify are both mutation-proven live by the checker: **P3** (planted an `intakeText` column plus text appended to `promptVersion` in `ai-audit.service.ts` → **both** `"persists ids, versions, flags and costs only"` cases FAILED — the key-set equality is real) and **P1** (planted the caught `message` into the infra-fallback `detectorFlags` → `"writes an AiAuditLog row on the final-attempt infra-fallback path"` FAILED — exact-equality + `not.toContain("db down")`).
- The plan's §3 AC3 table never asked for a call-site closed-set assertion on either path; the executor implemented the declared test surface faithfully and completely.

Distinguished from the T089-F2 "untested wiring" precedent, which **was** blocking: there, a wired behaviour had *no* coverage at all, so both the behaviour and its regressions were unverified. Here the wiring is positively verified (row written on the chat path; flags demonstrably flow from the builder into the entry via `arrayContaining(["DOSING"])`; failure resilience covered), and the primary content-freedom defences are mutation-proven. What is missing is only the *negative* "and nothing else" assertion at the call site — a regression guard, not the behaviour.

Prescription for the next task touching this area (cheap, restores symmetry with the infra-fallback case which already has it):
- `chat.service.spec.ts` — in `"writes an AiAuditLog row on the chat path"`, assert `entry.detectorFlags` `toEqual([])`, and in the gate-fires case assert every element is in `AI_AUDIT_FLAG_CODES` (or `toEqual` the exact array).
