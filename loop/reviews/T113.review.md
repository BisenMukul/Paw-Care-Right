## 12. Findings

**FINDING 1 — HIGH — the CI fingerprint steps cannot run: the `--` separator breaks the invocation.**
`.github/workflows/ci.yml` (both diff steps) invokes:
```
pnpm ota:fingerprint -- --base "$GITHUB_WORKSPACE/base-android.json" --platform android --out-dir "$GITHUB_WORKSPACE"
```
pnpm 10 forwards the literal `--` to the script, and `fingerprint-diff.sh`'s `*)` arm rejects it.
Reproduced with the **exact CI-pinned pnpm** (`packageManager: pnpm@10.34.3`, `action-setup`
`version: 10.34.3`, local `pnpm --version` → `10.34.3`):
```
$ cd apps/mobile && pnpm ota:fingerprint -- --dry-run --platform ios
> sh scripts/fingerprint-diff.sh -- --dry-run --platform ios
fingerprint-diff: unknown argument '--' -- usage: sh scripts/fingerprint-diff.sh --base <fingerprint-json> …
ELIFECYCLE  Command failed with exit code 1.
```
The identical command **without** `--` exits 0 and prints the plan. So on every PR the job produces **no
fingerprint diff whatsoever** — the card's "CI step printing fingerprint diff per PR" and AC2's CI half
are not met. Root cause of the miss: the plan itself specified the `--` form (step 11) and the executor
validated only `sh scripts/fingerprint-diff.sh …` directly, never the `pnpm ota:fingerprint` indirection
that CI actually uses. Fix: drop `--` in both steps; add a spec that pins the invocation form.

**FINDING 2 — MEDIUM — `| tee` masks the failure, so the broken job stays green.**
Both steps wrap the command in `{ … } | tee -a "$GITHUB_STEP_SUMMARY"`. GitHub's default `run` shell is
`bash -e {0}` — **no `pipefail`** — so the pipeline's exit status is `tee`'s, always 0. Reproduced locally
with `bash -e`: a failing command inside the group gives `STEP_EXIT=0`, and because `-e` aborts the group
the closing fence never prints, leaving a truncated summary containing no diff. This falsifies the job's
own comment ("Informational by construction: it fails only if the tooling itself fails … NEVER because the
fingerprint changed") — as written it *never* fails — and it is the functional equivalent of the
`|| true` masking that `ota-config.test.ts:163` explicitly forbids in the script. Combined with FINDING 1
the failure mode is the worst kind: green job, silent no-op. Fix: `set -o pipefail` in the run block, or
capture to a file and append it, so tool failure is visible while a *changed fingerprint* still exits 0
(which the script already guarantees).

**FINDING 3 — LOW — nothing pins the lazy-require / import-time safety.**
My mutation 3 replaced `defaultLoader`'s in-function `try/catch` require with an **eager module-top**
`require("expo-updates")` and all 15 tests stayed green, because the file-scope
`jest.mock("expo-updates", …)` makes the module always resolvable in the test environment. The shipped
code is correct; the property "the native module is never required at import time" (the Expo Go /
missing-binding safety that F6 exists to protect) is simply unguarded. A `jest.mock` factory that throws,
or an `isolateModules` import-only assertion, would pin it.

**FINDING 4 — LOW — pinned fingerprint version duplicated.** `0.20.5` appears both as
`FINGERPRINT_VERSION="0.20.5"` in `fingerprint-diff.sh:21` and twice literally in `ci.yml`'s "Generate
base fingerprints" step. Two places to bump; `ota-config.test.ts:161` pins only the script's copy.

**FINDING 5 — LOW — the CI pin is substring-only.** `ota-config.test.ts:149` asserts four substrings and
does **not** pin `if: github.event_name == 'pull_request'` nor the invocation form. This is what let
FINDING 1 through: a test that spawned the package script (`pnpm ota:fingerprint --dry-run`) rather than
only `sh <script> --dry-run` would have caught it immediately.

**FINDING 6 — LOW/nit — runbook §7 wording.** "`updates.url` is derived from `extra.eas.projectId`" —
both actually derive from the shared `EAS_PROJECT_ID` const; `updates.url` is not derived *from*
`extra.eas.projectId`. Harmless and directionally right.

**NOTE (not a finding) — FLAKE-2 stash methodology.** Flawed as executed (see §9) but the conclusion is
sound and the tree is verifiably intact. Worth correcting the habit: use `git stash -u` or, better, a
`git worktree` at the baseline commit rather than stashing a live tree.
